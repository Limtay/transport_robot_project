# AksIM-2 비동기 시리얼(RS422 UART) 인터페이스 — STM32 구현 규격서

**대상 하드웨어**: RLS AksIM-2, 리드헤드 `MB029`(형상 F, 커넥터 N), 링 `MRA029BC010DSE00` 또는 `MRA029GP013DMN00` **출처**: RLS 데이터시트 `MBD01_15` (Issue 15, 2026-05-13), p.27 / p.29 / p.31 / p.35–39 / p.54 **전제**: 통신 인터페이스 변형이 `SF`(Asynchronous serial, RS422)로 확정된 경우

> ⚠️ 파트넘버가 아직 확정 전이라면 이 문서를 적용하기 전에 `'v'` 명령으로 파트넘버 16자리를 먼저 확인할 것. 3~4번째 필드가 `SF`가 아니면(예: `DC` = BiSS C) 이 문서는 적용되지 않는다.

---

## 1. 인터페이스 개요

AksIM-2의 비동기 시리얼은 **요청-응답(request-response)** 방식이다. 마스터(STM32)가 ASCII 명령 1바이트를 보내면 엔코더가 정해진 길이의 바이너리 패킷으로 응답한다.

물리 계층은 **단방향 채널 2개로 구성된 풀듀플렉스 양방향 링크**다. 각 채널은 RS422 규격을 따르는 2선 차동 트위스티드 페어다.

```
        STM32                          AksIM-2 (MB029)
    ┌───────────┐                     ┌──────────────┐
    │  USART_TX ├──► [RS422 Driver] ══╪══► RX Cmd ±   │   (핀 5/6)
    │           │                     │              │
    │  USART_RX ◄── [RS422 Receiver]══╪══ TX Data ±  │   (핀 7/8)
    └───────────┘                     └──────────────┘
```

### 1.1 RS485와의 결정적 차이 — DE/RE 제어가 없다

X-Track의 Orin↔STM32 RS485 링크는 반이중이라 방향 전환(DE/RE) 타이밍이 필요하다. **이 인터페이스는 그게 없다.**

- 송신 페어와 수신 페어가 물리적으로 분리되어 있다
- 드라이버는 항상 인에이블, 리시버도 항상 인에이블
- 전이중 트랜시버(예: MAX3490)를 쓰거나, 반이중 트랜시버 2개를 각각 `DE=High` / `RE=Low` 고정으로 써도 된다
- 버스에 여러 노드를 붙일 수 없으므로 **엔코더 1개당 USART 1채널 전용**

이 차이 때문에 기존 `rd_uart` 드라이버의 방향 제어 로직을 그대로 재사용하면 안 된다. 오히려 IMU(UART6) 쪽 구조가 더 가깝다.

### 1.2 통신 파라미터 (p.35)

|항목|값|
|---|---|
|Character length|8 bits|
|Parity|**None**|
|Stop bits|**1**|
|Flow control|**None**|
|프레임 형식 요약|**8N1**|
|Request rate|보드레이트가 허용하는 최대치. 패킷 간 지연 없이 연속 전송 가능|
|Mechanical sample rate|18 kHz|
|Bandwidth|9 kHz (기계적 대역폭)|
|Position latency|**< 10 µs** (매 전송마다 재계산)|

### 1.3 보드레이트 (p.35)

링크 속도는 파트넘버의 **통신 인터페이스 변형** 문자로 공장 설정된다.

|변형|A|B|C|D|E|F|G|
|---|---|---|---|---|---|---|---|
|kbps|115.2|128|230.4|256|500|**1,000**|921.6|

- 필드에서 변경 가능(APP10 앱노트 절차). 변경 후 설정은 재프로그래밍 전까지 영구 유지
- p.29 기준 300 baud ~ 1 Mbaud 범위로 설정 가능
- **파트넘버를 모르면 위 7개 값을 순차로 스윕**하면서 `'v'` 응답이 오는 속도를 찾으면 된다

### 1.4 비트/바이트 순서 (p.35)

> "Data is transmitted LSB first; big-endian order."

두 개를 분리해서 읽어야 한다:

- **LSB first** — UART 비트 순서. 표준 UART 그대로이므로 STM32 기본 설정(`UART_ADVFEATURE_...` 건드릴 것 없음)
- **big-endian order** — 바이트 순서. **멀티바이트 값은 MSB 바이트가 먼저 온다**

즉 위치 3바이트가 `[B2][B3][B4]` 순으로 오면 `B2`가 최상위 바이트다. STM32는 리틀엔디안이므로 `memcpy`로 통째로 캐스팅하면 안 되고, 반드시 시프트+OR로 조립해야 한다.

## 2. 전기적 연결

### 2.1 핀맵 (p.27, p.54)

리드헤드 8핀 커넥터 및 ACC 케이블 색상:

|커넥터 핀|DSUB-9 핀|케이블 색|신호 (Async serial)|
|---|---|---|---|
|—|1|Shield|실드|
|1|5|갈색|**5 V supply**|
|2|9|흰색|**0 V (GND)**|
|3|8|분홍|외부 온도센서 pin 1 (패스스루)|
|4|4|회색|외부 온도센서 pin 2 (패스스루)|
|5|2|빨강|**RX Command in +**|
|6|3|파랑|**RX Command in −**|
|7|6|초록|**TX Data out +**|
|8|7|노랑|**TX Data out −**|

- 5/6이 한 페어, 7/8이 한 페어. 트랜시버까지 페어 유지 필수
- 3/4번은 엔코더 회로와 절연된 단순 패스스루. 미사용 시 개방
- 커넥터 짝: 하우징 `10114826-00008LF` + 터미널 `10114827-002LF` × 8 (Amphenol FitMate 1.25)

### 2.2 전원 (p.4)

|항목|값|
|---|---|
|공급 전압|4.5 ~ 5.5 V (커넥터 기준)|
|**상승 시간**|**20 ms 이내**|
|소비 전류|typ 130 mA, max 150 mA (출력 무부하)|
|Set-up time|100 ms (최초 데이터 유효), 최악 200 ms|

**상승 시간 20ms 제약이 중요하다.** 이보다 느리면 System error 비트(b2)가 셋될 수 있고, 반대로 System error 복구 시에도 "20ms보다 빠른 상승 시간으로 전원을 재인가"하라고 명시돼 있다. X-Track 전원 시퀀싱에서 5V 레일에 큰 벌크 커패시터가 물려 있으면 확인 필요.

펌웨어는 **전원 인가 후 최소 200 ms 대기** 후 첫 요청을 보내야 한다. 이 구간은 `LS_INIT` 상태로 두고 `LS_RUNNING` 승격을 지연시키는 게 맞다.

### 2.3 종단 (p.35)

- Command / Data 신호는 5V RS422 호환 차동 페어이며, **리드헤드 내부에 RC 종단이 이미 들어 있다**
- **총 케이블 길이가 5 m를 넘으면 컨트롤러 측 종단 필요**. 케이블 공칭 임피던스 120 Ω
- X-Track 배선 길이(1~3 m 예상)면 컨트롤러 측 종단 불필요

### 2.4 출력 보호 (p.35)

과전류·과전력에 대해 두 가지 보호가 있다. 출력단 폴드백 전류 제한이 단락에 대해 즉시 동작하고, 칩 온도가 과도해지면 열 셧다운이 드라이버 출력을 하이임피던스로 강제한다.

→ **하이임피던스 상태에서는 수신 라인이 플로팅**이 된다. 리시버 측에 페일세이프 바이어싱이 없는 트랜시버를 쓰면 노이즈가 랜덤 바이트로 들어올 수 있으니, 페일세이프 내장 부품을 쓰거나 바이어스 저항을 넣을 것.

## 3. 명령 세트

명령은 **ASCII 1바이트**다. CR/LF 등 종단 문자 불필요.

### 3.1 명령 일람 (p.36)

괄호 안 숫자는 멀티턴 옵션(`17M`/`18M`)일 때의 길이다.

|명령|총 응답 길이 (싱글턴 / 멀티턴)|응답 구성|
|---|---|---|
|`'1'`|4 / 6 B|헤더 `'1'` + 위치 3(5)B|
|`'3'`|**3 / 5 B**|위치 3(5)B **만** (헤더 없음)|
|`'d'`|6 / 8 B|헤더 `'d'` + 위치 3(5)B + 상세 상태 2B|
|`'j'`|6 / 8 B|헤더 `'j'` + 위치 3(5)B + 영속 상세 상태 2B|
|`'s'`|7 / 9 B|헤더 `'s'` + 위치 3(5)B + 속도(RPM) 3B|
|`'t'`|5 / 7 B|헤더 `'t'` + 위치 3(5)B + 센서 온도 1B|
|`'a'`|6 / 8 B|헤더 `'a'` + 위치 3(5)B + 신호 레벨 2B|
|`'i'`|8 B|헤더 `'i'` + 자가 캘리브레이션 상태 7B|
|`'v'`|59 B|헤더 `'v'` + 버전/시리얼 정보 58B|

### 3.2 응답 규칙 (p.36)

1. **`'3'`은 헤더를 되돌려주지 않는다.** 가장 짧은 응답을 원할 때 쓰는 전용 명령
2. 그 외 모든 명령은 **명령과 동일한 헤더 바이트를 먼저 회신**한다. 이 헤더로 어떤 패킷 포맷으로 디코딩할지 판별할 수 있다
3. 헤더 다음에는 **명령 종류와 무관하게 항상 위치 데이터가 먼저** 온다 (`'i'`, `'v'` 제외)
4. 그 뒤에 명령별 추가 바이트가 붙는다
5. **잘못된 명령을 보내면 헤더 바이트만 회신되고 추가 데이터는 없다**

5번은 파서 설계에 중요하다. 잡음으로 깨진 바이트가 명령으로 해석되면 예상보다 짧은 응답이 오므로, 길이 기반 프레이밍만으로는 어긋난다. → §6.3의 IDLE 검출 기반 재동기화 필요.

### 3.3 200 Hz 루프에서의 선택

주기적 제어 루프에서는 **`'3'`이 최선**이다.

- 왕복 바이트 수가 최소(TX 1B + RX 3B)
- 헤더 파싱 오버헤드 없음
- 에러/워닝 비트가 위치 데이터에 통합되어 있어 최소한의 유효성 판단은 가능

상세 상태는 저주기(예: 10 Hz)로 `'d'`를 끼워 넣거나, 에러 비트가 뜬 직후에만 `'d'`를 발행하는 방식이 효율적이다.

## 4. 위치 데이터 패킷 구조 (p.36)

### 4.1 공통 규칙

- 싱글턴 변형은 **3바이트**, 멀티턴 변형은 **5바이트**
- 위치는 **항상 좌측 정렬(left aligned)**, 멀티턴 데이터가 앞에 온다
- 에러/워닝 비트는 **항상 우측 정렬**: 에러 = `b1`, 워닝 = `b0`
- 위치 LSB와 에러 비트 사이는 **0 패딩**
- 에러/워닝 비트는 **반전 전송(active low)**

### 4.2 비트 배치 — 싱글턴 (24비트 필드, b23..b0)

|분해능|위치 비트|0 패딩|에러/워닝|
|---|---|---|---|
|17B|b23 – b7|b6 – b2|b1, b0|
|**18B**|**b23 – b6**|**b5 – b2**|b1, b0|
|19B|b23 – b5|b4 – b2|b1, b0|
|20B|b23 – b4|b3 – b2|b1, b0|

> **MB029는 17B / 18B / 17M / 18M만 가능** (p.48 조합표). 19B·20B는 물리적으로 존재하지 않으므로 파서에서 지원할 필요 없음.

### 4.3 비트 배치 — 멀티턴 (40비트 필드, b39..b0)

|분해능|위치 비트 (MT+ST 통합)|0 패딩|에러/워닝|
|---|---|---|---|
|17M|b39 – b7|b6 – b2|b1, b0|
|**18M**|**b39 – b6**|**b5 – b2**|b1, b0|

18M 기준 세부 분해:

```
b39 ─────────── b24 │ b23 ─────────── b6 │ b5 ── b2 │ b1 │ b0
   멀티턴 카운터 16b  │   싱글턴 위치 18b   │  0 패딩   │ E  │ W
```

### 4.4 에러/워닝 비트 의미 (active low)

|비트|값 0|값 1|
|---|---|---|
|`b1` (Error)|**위치 무효**|정상|
|`b0` (Warning)|위치는 유효하나 동작 한계 근접 (분해능/정확도 규격 미달 가능)|정상|

- 에러 발생 시 **마지막 유효 데이터가 그대로 전송**된다. 즉 값이 갱신되지 않고 고정된다
- 값이 멈춰 보이는 현상을 스케일 팩터 버그로 오진하지 말 것 (CAN 모터 드라이버에서 겪었던 것과 같은 증상이 여기서도 나올 수 있음)
- 에러와 워닝은 동시에 셋 가능하며, 이 경우 **에러가 우선**

### 4.5 파싱 코드 (C)

```c
#include <stdint.h>

typedef struct {
    uint32_t position;      // 0 .. (2^bits - 1)
    uint16_t multiturn;     // 멀티턴 변형에서만 유효
    uint8_t  error;         // 1 = 에러 발생 (원본 비트를 반전해서 저장)
    uint8_t  warning;       // 1 = 워닝 발생
} AksIM_Position_t;

/* ---- 18B 싱글턴 (3바이트) ---- */
static inline void AksIM_Parse18B(const uint8_t *rx, AksIM_Position_t *out)
{
    uint32_t raw = ((uint32_t)rx[0] << 16)   /* big-endian: rx[0]이 MSB */
                 | ((uint32_t)rx[1] <<  8)
                 |  (uint32_t)rx[2];

    out->position  = (raw >> 6) & 0x0003FFFFu;   /* b23..b6, 18비트 */
    out->error     = ((raw >> 1) & 1u) ? 0u : 1u; /* active low 반전 */
    out->warning   = ((raw >> 0) & 1u) ? 0u : 1u;
    out->multiturn = 0;
}

/* ---- 17B 싱글턴 (3바이트) ---- */
static inline void AksIM_Parse17B(const uint8_t *rx, AksIM_Position_t *out)
{
    uint32_t raw = ((uint32_t)rx[0] << 16)
                 | ((uint32_t)rx[1] <<  8)
                 |  (uint32_t)rx[2];

    out->position  = (raw >> 7) & 0x0001FFFFu;   /* b23..b7, 17비트 */
    out->error     = ((raw >> 1) & 1u) ? 0u : 1u;
    out->warning   = ((raw >> 0) & 1u) ? 0u : 1u;
    out->multiturn = 0;
}

/* ---- 18M 멀티턴 (5바이트) ---- */
static inline void AksIM_Parse18M(const uint8_t *rx, AksIM_Position_t *out)
{
    uint64_t raw = ((uint64_t)rx[0] << 32)
                 | ((uint64_t)rx[1] << 24)
                 | ((uint64_t)rx[2] << 16)
                 | ((uint64_t)rx[3] <<  8)
                 |  (uint64_t)rx[4];

    out->multiturn = (uint16_t)((raw >> 24) & 0xFFFFu);        /* b39..b24 */
    out->position  = (uint32_t)((raw >>  6) & 0x0003FFFFu);    /* b23..b6  */
    out->error     = ((raw >> 1) & 1u) ? 0u : 1u;
    out->warning   = ((raw >> 0) & 1u) ? 0u : 1u;
}
```

### 4.6 카운트 → 각도 변환

```c
/* 18비트: 262144 counts/rev */
#define AKSIM_BITS        18u
#define AKSIM_COUNTS      (1u << AKSIM_BITS)     /* 262144 */
#define AKSIM_DEG_PER_CNT (360.0f / (float)AKSIM_COUNTS)  /* ≈ 0.001373° */

float angle_deg = (float)out.position * AKSIM_DEG_PER_CNT;
```

|분해능|counts/rev|1 count의 각도|
|---|---|---|
|17B|131,072|0.002747°|
|18B|262,144|0.001373°|

참고: MB029 + MRA029 조합의 시스템 정확도는 ±0.014°, 캘리브레이션 후 설치 정확도 ±0.023°, 미캘리브레이션 ±0.070°다. **분해능이 정확도보다 한 자릿수 이상 좋으므로**, 절대 각도 정밀도를 분해능으로 착각하면 안 된다. 제어 루프의 미분항(속도 추정)에는 분해능이 유효하지만, 절대 위치 오차 예산에는 정확도 값을 써야 한다.

## 5. 부가 데이터 패킷

### 5.1 `'d'` / `'j'` — 상세 상태 2바이트 (p.39)

응답: `['d'][pos 3B or 5B][status_hi][status_lo]`

**주의: 이 2바이트의 비트는 active-high다.** 위치 패킷의 E/W 비트(active low)와 극성이 반대이므로 혼동 금지.

#### 상위 바이트 (b15..b8)

|비트|등급|의미|조치|
|---|---|---|---|

- **간헐적 통신 오류 디버깅에 매우 유용하다.** CAN STF/FOR 에러 추적할 때 TEC/REC 카운터를 봤던 것과 같은 용도

### 5.2 `'s'` — 회전 속도

응답: `['s'][pos 3B or 5B][spd_hi][spd_mid][spd_lo]`

3바이트 **부호 있는 바이너리, 단위 RPM**. 24비트 부호 확장 필요:

```c
static inline int32_t AksIM_ParseSpeed(const uint8_t *p)
{
    int32_t v = ((int32_t)p[0] << 16) | ((int32_t)p[1] << 8) | (int32_t)p[2];
    if (v & 0x00800000) { v |= (int32_t)0xFF000000; }  /* 24→32비트 부호 확장 */
    return v;   /* RPM */
}
```

엔코더 내부 계산 속도이므로 STM32에서 위치를 수치 미분하는 것보다 노이즈가 적다. MPC의 상태 추정에 쓸 만하다.

### 5.3 `'t'` — 센서 온도

응답: `['t'][pos 3B or 5B][temp]`

1바이트 **부호 있는 바이너리, 단위 °C**.

- **주변 온도보다 통상 5~15 °C 높게** 나온다 (리드헤드 자체 발열)
- 판독 공차 **±5 °C**
- 절대 온도계로 쓰지 말고 추세 감시·과열 검출용으로만 사용

```c
int8_t temp_c = (int8_t)rx[n];   /* 그대로 부호 있는 8비트 */
```

### 5.4 `'a'` — 신호 레벨 → 라이드 하이트 환산

응답: `['a'][pos 3B or 5B][sig_hi][sig_lo]`

2바이트 **부호 없는 바이너리**. 이 값은 센서와 링 표면(고무) 사이 거리에 비례한다.

실제 거리 환산식 (p.23):

```
Ride height [µm] = K × ln(SignalLevel) + N
```

|엔코더 사이즈|K|N|
|---|---|---|
|**022, 029**|**−95.49**|**977**|
|039, 049|−83.56|865|
|053, 064, 080|−71.62|748|

- `ln`은 자연로그
- 계산된 라이드 하이트의 공차는 **±20 µm**
- 목표 범위: **0.05 ~ 0.35 mm** (50 ~ 350 µm)
- 라이드 하이트가 커질수록 노이즈가 **지수적으로** 증가하므로, 공차 내에서도 최대한 낮게 맞출 것

```c
#include <math.h>

/* MB029 전용 */
static inline float AksIM_RideHeight_um(uint16_t signal_level)
{
    if (signal_level == 0u) { return NAN; }
    return -95.49f * logf((float)signal_level) + 977.0f;
}
```

**조립 검증 시퀀스에 넣기 좋다.** 부팅 시 `'a'` 한 번 읽어서 라이드 하이트가 50~350 µm 밖이면 기구 조립 불량으로 판정하고 `LS_OFFLINE`으로 보내는 식.

### 5.5 `'i'` — 자가 캘리브레이션 상태 (Issue 15에서 개정됨)

응답: `['i'][B2][B3][B4][B5][B6][B7][B8]` — 총 8바이트

|바이트|내용|
|---|---|
|B2|자가 캘리브레이션 상태 (상세 코드는 앱노트 `APP10` 참조)|
|B3–B4|링 편심 (unsigned, µm)|
|B5–B6|링 편심 위상 (unsigned, deg)|
|B7–B8|리드헤드 반경방향 변위 (**signed**, µm)|

> 이 명령의 응답 포맷은 데이터시트 Issue 15(2026-05-13)에서 개정되었다. 구버전 문서나 예제 코드를 참고할 경우 반드시 Issue 15 기준으로 확인할 것.

**측정된 링 편심이 0.2 mm(200 µm)를 넘으면 기구 조립을 재조정하는 것이 권장된다.** 이 값은 조립 품질을 정량화하는 유일한 수단이므로, X-Track 조립 절차서에 체크 항목으로 넣어둘 가치가 있다.

### 5.6 `'v'` — 버전 및 시리얼 정보

응답: 총 **59바이트**

|바이트|내용|
|---|---|
|B1|ASCII 헤더 `'v'`|
|B2–B8|ASCII 식별 문자열 `"AksIM-2"` (7자)|
|B9|공백 문자|
|B10–B17|ASCII 시리얼 넘버 (8자)|
|B18|공백 문자|
|**B19–B34**|**ASCII 파트넘버 (16자)**|
|B35|공백 문자|
|B36|펌웨어 major 버전 (바이너리)|
|B37|펌웨어 minor 버전 (바이너리)|
|B38|통신 인터페이스 버전 (바이너리)|
|B39–B42|펌웨어 리비전 번호 (바이너리 4B)|
|B43|공백 문자|
|B44–B59|ASCII 확장 시리얼 넘버 (16자)|

**B19–B34가 파트넘버 확정의 열쇠다.** 여기서 분해능(`17B`/`18B`/`17M`/`18M`)과 통신 변형을 읽어 런타임에 파서를 선택하도록 구현하면, 하드웨어 교체 시 펌웨어 수정 없이 대응할 수 있다.

```c
typedef struct {
    char     id[8];          /* "AksIM-2" + NUL */
    char     serial[9];      /* 8자 + NUL */
    char     part_number[17];/* 16자 + NUL */
    uint8_t  fw_major;
    uint8_t  fw_minor;
    uint8_t  comm_version;
    uint32_t fw_revision;
    char     ext_serial[17];
} AksIM_Version_t;

static void AksIM_ParseVersion(const uint8_t *rx, AksIM_Version_t *v)
{
    /* rx[0] == 'v' */
    memcpy(v->id,          &rx[1],  7);  v->id[7]           = '\0';
    memcpy(v->serial,      &rx[9],  8);  v->serial[8]       = '\0';
    memcpy(v->part_number, &rx[18],16);  v->part_number[16] = '\0';
    v->fw_major     = rx[35];
    v->fw_minor     = rx[36];
    v->comm_version = rx[37];
    v->fw_revision  = ((uint32_t)rx[38] << 24) | ((uint32_t)rx[39] << 16)
                    | ((uint32_t)rx[40] <<  8) |  (uint32_t)rx[41];
    memcpy(v->ext_serial,  &rx[43],16);  v->ext_serial[16]  = '\0';
}
```

## 6. STM32 구현 설계

### 6.1 타이밍 예산

8N1이므로 **바이트당 10비트**다.

|보드레이트|바이트당 시간|`'3'` 왕복 (TX 1B + RX 3B)|`'d'` 왕복 (TX 1B + RX 6B)|
|---|---|---|---|
|115.2 k|86.8 µs|347 µs|608 µs|
|230.4 k|43.4 µs|174 µs|304 µs|
|500 k|20.0 µs|80 µs|140 µs|
|921.6 k|10.9 µs|43 µs|76 µs|
|**1 M**|**10.0 µs**|**40 µs**|**70 µs**|

여기에 엔코더 내부 지연 < 10 µs를 더하면 된다. **200 Hz 루프(5 ms 주기)에서는 최저 보드레이트인 115.2 k로도 여유가 크다.**

다만 X-Track이 엔코더를 여러 개 쓴다면(트랙별 4개 등) 채널을 병렬로 돌리든지 순차 폴링 시간을 합산해야 한다. 115.2 k × 4채널 순차면 1.4 ms — 여전히 5 ms 안에 들어가지만, DMA로 병렬화하는 게 지터 측면에서 낫다.

### 6.2 위치 래치 시점 — 타임스탬프 동기화와의 연결

p.31에 따르면 **위치는 명령 바이트의 첫 비트에서 래치**되고 새 위치값이 즉시 계산되므로 지연은 10 µs 미만이다.

이건 X-Track의 `delta_tick` 타임스탬프 체계에 그대로 매핑된다:

- 래치 시점 = **명령 바이트 송신 시작 시각**
- TIM5(10 kHz, 100 µs 단위)로 명령 송신 직전에 타임스탬프를 캡처하면, 그 값이 곧 물리적 측정 시각
- 응답 수신 완료 시각이 아니라 **송신 시작 시각**을 기록해야 한다. 이걸 반대로 잡으면 보드레이트에 비례하는 계통 오차가 들어간다
- 10 µs 지연은 100 µs 단위 델타 인코딩에서 0.1 LSB이므로 무시 가능

```c
/* 송신 직전에 타임스탬프 캡처 */
uint32_t ts = __HAL_TIM_GET_COUNTER(&htim5);   /* 10 kHz free-running */
HAL_UART_Transmit_DMA(&huart_enc, &cmd, 1);
/* ts를 이 샘플의 측정 시각으로 기록 */
```

### 6.3 프레이밍 및 재동기화 — CRC가 없다는 문제

**이 인터페이스에는 위치 패킷 CRC가 없다.** BiSS C(6비트 CRC, 다항식 0x43)나 SPI(0x97)와 달리, UART 위치 패킷은 에러/워닝 비트 2개만 제공한다. 또한 X-Track의 자체 RS485 프로토콜과 달리 **동기 바이트(0xAA/0x55)도 길이 필드도 없다.**

즉 **바이트 스트림이 한 번 어긋나면 스스로 복구할 방법이 프로토콜에 없다.** 반드시 펌웨어에서 방어해야 한다.

#### 방어책 1 — IDLE 라인 검출 기반 프레이밍

요청-응답 방식이므로 응답 패킷 사이에는 반드시 유휴 구간이 생긴다. STM32의 USART IDLE 인터럽트 + DMA 조합이 정석이다.

```c
/* 초기화 */
__HAL_UART_ENABLE_IT(&huart_enc, UART_IT_IDLE);
HAL_UART_Receive_DMA(&huart_enc, rx_buf, RX_BUF_SIZE);

/* IDLE 인터럽트 핸들러 */
void AksIM_IdleCallback(void)
{
    uint16_t received = RX_BUF_SIZE - __HAL_DMA_GET_COUNTER(huart_enc.hdmarx);

    if (received == expected_len) {
        AksIM_Parse18B(rx_buf, &g_encoder);
        g_rx_ok++;
    } else {
        /* 길이 불일치 = 프레이밍 깨짐 → 버리고 재무장 */
        g_rx_framing_err++;
    }

    /* 매 요청마다 DMA를 재무장해 링버퍼 desync를 원천 차단 */
    HAL_UART_AbortReceive(&huart_enc);
    HAL_UART_Receive_DMA(&huart_enc, rx_buf, RX_BUF_SIZE);
}
```

> 기존 UART 드라이버에서 겪었던 "DMA 재무장 시 링버퍼 desync" 문제가 여기서도 재현될 수 있다. 이 인터페이스는 요청-응답이라 **매 트랜잭션마다 버퍼를 처음부터 다시 채우는 방식**이 가능하므로, 연속 스트림용 링버퍼보다 이 구조가 안전하다.

#### 방어책 2 — 응답 타임아웃

명령 송신 후 `(예상 바이트 수 × 바이트 시간 × 2 + 100 µs)` 안에 IDLE이 오지 않으면 실패 처리. 200 Hz 루프에서는 타임아웃을 1 ms 정도로 잡고, 연속 N회 실패 시 `LS_OFFLINE` 강등.

#### 방어책 3 — 위치 타당성 검사 (CRC 대체)

CRC가 없으므로 **물리적 제약으로 무결성을 검증**한다. 이전 샘플 대비 위치 변화량이 기구적으로 불가능한 크기면 그 샘플을 버린다.

```c
/* 예: 최대 각속도 ω_max [rev/s], 샘플 주기 T [s] */
#define MAX_DELTA_COUNTS  ((uint32_t)(OMEGA_MAX_RPS * AKSIM_COUNTS * T_SAMPLE * 1.5f))

static uint32_t prev_pos;
static uint8_t  prev_valid = 0;

uint8_t AksIM_PlausibilityCheck(uint32_t pos)
{
    if (!prev_valid) { prev_pos = pos; prev_valid = 1; return 1; }

    /* 랩어라운드를 고려한 최단 거리 */
    int32_t d = (int32_t)pos - (int32_t)prev_pos;
    if (d >  (int32_t)(AKSIM_COUNTS/2)) { d -= (int32_t)AKSIM_COUNTS; }
    if (d < -(int32_t)(AKSIM_COUNTS/2)) { d += (int32_t)AKSIM_COUNTS; }

    if ((uint32_t)((d < 0) ? -d : d) > MAX_DELTA_COUNTS) {
        return 0;   /* 기구적으로 불가능 → 비트 오류로 판단하고 폐기 */
    }
    prev_pos = pos;
    return 1;
}
```

**주의**: 이 검사는 샘플링 주기 안에 회전이 반 바퀴를 넘지 않는다는 전제에서만 유효하다. 200 Hz(5 ms)에 18비트면 반 바퀴 = 131,072 counts인데, MB029 최대 속도 10,000 RPM에서는 5 ms에 0.83 바퀴를 돌아 이 전제가 깨진다. X-Track 트랙 회전 속도가 실제로 어느 정도인지 확인하고 `MAX_DELTA_COUNTS`를 보수적으로 설정할 것.

#### 방어책 4 — 주기적 `'j'` 폴링

저주기(1~10 Hz)로 영속 상세 상태를 읽어 누적 에러를 감시. 순간적으로 발생했다 사라진 이상도 잡히므로, 필드에서 재현 안 되는 간헐 문제를 추적할 때 결정적이다.

### 6.4 채널 배정 검토

현재 STM32F446 사용 현황:

|채널|현재 용도|
|---|---|
|CAN1|AK 모터 4개 (1 Mbps, 점유율 약 22%)|
|UART1|RC 컨트롤러|
|UART2|RS485 / Orin (460800)|
|UART4|(드라이버 상 IMU 채널로 관리)|
|UART6|IMU|
|I2C|AS5600 인코더 5개 (MUX 경유)|

AksIM-2를 붙이려면 **여유 USART가 필요**하다. F446은 USART1/2/3/6 + UART4/5가 있으므로 USART3 또는 UART5가 후보다. DMA 스트림 가용성(특히 DMA1 스트림 충돌)을 먼저 확인할 것.

**AS5600을 AksIM-2로 대체하는 경우** I2C MUX 구조가 통째로 사라지고 채널당 USART 1개가 필요해진다. 5개 전부 교체하려면 USART가 부족하므로, 이때는 UART 변형이 아니라 **SPI 변형(`SP`)을 고려**하는 게 합리적이다. SPI는 NCS만 개별로 주면 라인 공유가 가능해서(데이터시트 p.40이 명시) 채널 하나로 다중 엔코더를 처리할 수 있다.

> UART 변형은 **엔코더 1~2개**를 붙일 때 적합하고, 다수 붙일 거면 SPI 변형 재검토를 권한다. 이건 파트넘버 발주 전에 결정해야 하는 사안이다.

### 6.5 초기화 시퀀스 (권장)

```
1. 5V 인가 (상승시간 < 20 ms 확인)
2. 200 ms 대기                          ← set-up time 최악값
3. 'v' 송신 → 59바이트 수신
   ├─ "AksIM-2" 문자열 확인             ← 통신 링크 정상 확인
   ├─ 파트넘버 파싱 → 분해능/변형 결정   ← 파서 선택
   └─ 실패 시 보드레이트 스윕 후 재시도
4. 'a' 송신 → 신호 레벨 → 라이드 하이트 계산
   └─ 50~350 µm 범위 밖이면 조립 불량 경고
5. 'i' 송신 → 링 편심 확인
   └─ 200 µm 초과 시 재조립 권고 로그
6. 'j' 송신 → 영속 상태 확인 후 클리어
7. LS_INIT → LS_RUNNING 승격
8. 200 Hz 루프에서 '3' 폴링 시작
```

## 7. 엔코더 프로그래밍 (p.39)

비동기 시리얼 인터페이스로 다음을 설정할 수 있다:

- 기본 보드레이트 변경
- 자가 캘리브레이션 실행
- 신호 레벨, 온도, 상세 상태 비트 읽기
- **선택한 데이터 패킷을 프로그래밍 가능한 프레임 레이트로 자동 전송하도록 설정**

마지막 항목이 흥미롭다. 폴링 없이 엔코더가 자율적으로 주기 전송하게 만들 수 있다는 뜻인데, 이러면 STM32의 송신 부담이 사라지는 대신 타임스탬프 래치 시점을 마스터가 제어할 수 없게 된다. **X-Track처럼 다중 센서 시각 동기가 중요한 시스템에서는 폴링 방식이 맞다.**

레지스터 맵과 Unlock 시퀀스 등 구체적 절차는 앱노트 문서에 있다:

|문서 번호|내용|
|---|---|
|**APP10**|Programming encoders with Async serial interface — 이 인터페이스 전용|
|APP11|AksIM-2 BiSS C register access (BiSS 변형용)|
|MBD08|EncoLink 고수준 프로토콜 (SPI 변형용)|
|CRCD01|CRC 계산 루틴 예제|

전부 RLS Media center에서 다운로드. **APP10은 필수로 받아둘 것** — 이 문서에는 자가 캘리브레이션 상태 코드(`'i'`의 B2)와 영속 상태 클리어용 Unlock 시퀀스가 들어 있는데, 데이터시트 본문에는 없다.

### 7.1 자가 캘리브레이션 (p.25)

편심에 의한 오차를 제거한다. 통신 인터페이스를 통해 사용자가 실행할 수 있다(PWM·SSI에서는 불가).

**요구 조건**:

|항목|값|
|---|---|
|자유 회전 각도|180° ~ 360° (360°에서 최적, 각도가 줄면 성능 저하)|
|최소 속도|6 RPM|
|기본 소요 시간|10초 (통신 인터페이스로 최대 40초까지 설정 가능)|
|신호 품질|전체 캘리브레이션 각도에서 경고·에러 없어야 함|
|방향/속도 변동|무관|

**효과**: 미캘리브레이션 ±0.070° → 캘리브레이션 후 ±0.023° (MRA029 기준). 편심이 클수록 개선 폭이 커진다.

**결과 확인**: LED 3초 고속 점멸

|LED|의미|
|---|---|
|녹색 고속 점멸|캘리브레이션 성공|
|주황 고속 점멸|링 위치가 이미 완벽 — 보정 미수행 (상태 비트 0x20)|
|적색 고속 점멸|입력 파라미터 범위 초과(0x10) / 편심·반경 오프셋 과대(0x08) / 타임아웃, 6 RPM 미만(0x04)|

**멀티턴 주의**: 캘리브레이션 시 속도가 ±300 RPM을 넘으면 멀티턴 카운터 값이 잘못될 수 있고 멀티턴 에러 플래그가 셋된다.

## 8. 멀티턴 사용 시 주의사항 (p.30)

멀티턴 옵션(`17M`/`18M`)을 쓴다면 반드시 알아야 할 제약이다.

- 카운터는 **16비트 (0 ~ 65535 counts)**
- 카운팅은 **전원이 인가된 동안에만** 동작. 전원 차단 시 비휘발성 메모리에 저장되고 재인가 시 복원
- **전원 차단 중 허용 회전량은 ±90°**. 이를 초과하면 에러를 보고
- ±360° 또는 정수 배 회전은 등록되지 않으며 에러도 셋되지 않음(즉 조용히 틀어진다)
- 90° 이상 회전 중 다른 에러가 발생하면 멀티턴 값이 기계적 위치와 불일치할 수 있음

**사용자가 반드시 검증 방법을 구현해야 한다**고 데이터시트가 명시한다:

1. 전원 차단 전 기계식 브레이크 작동, 재인가 후 해제
2. 전원 인가 시마다 새 멀티턴 값을 프리셋
3. 기타 자체 검증 방법

X-Track의 수동 4절 링크 구조에서는 전원 차단 중에도 자중이나 외력으로 링크가 움직일 수 있으므로, **2번(부팅 시 프리셋)이 현실적**이다. 다른 절대 기준(리밋 스위치, 홈 포지션)과 조합해야 한다.

멀티턴 에러 플래그가 셋되는 조건:

- 전원 차단 중 90° 초과 270° 미만 움직임 감지
- 블로킹 동작(비휘발성 저장, 팩토리 리셋, 라이트 프로텍트, 자가 캘리브레이션) 중 300 RPM 초과 감지
- 예상치 못한 큰 위치 차이 감지(가속도 오류)

클리어 방법: 새 값 기입 또는 전원 재인가.

**멀티턴이 꼭 필요한 게 아니면 싱글턴(`18B`)을 권한다.** X-Track의 4절 링크 각도 측정이라면 회전 범위가 1회전 미만일 가능성이 높고, 그렇다면 멀티턴의 복잡성을 떠안을 이유가 없다.

## 9. 설치 및 환경 제약 (제어 성능에 직결되는 항목)

### 9.1 설치 공차 (p.23) — MB029 기준

|항목|허용치|
|---|---|
|축방향 변위 (라이드 하이트)|**0.05 ~ 0.35 mm**|
|접선방향 변위|±0.3 mm|
|**반경방향 변위**|**±0.3 mm** (MB029)|
|비평행 설치 (틸트)|< 0.2°|

라이드 하이트는 공차 내에서도 값이 커질수록 **노이즈가 지수적으로 증가**한다. 18비트 고분해능 옵션은 애초에 "노이즈를 포함할 수 있으며, 제어 루프의 부드러운 동작이나 평균화에 적합"하다고 데이터시트가 단서를 달아뒀다.

→ **18B로 받되, 제어에 쓸 때는 필터링을 전제로 설계할 것.** 원시값을 그대로 MPC 상태로 넣으면 미분항에서 노이즈가 증폭된다.

### 9.2 외부 자기장 (p.5) — 가장 큰 위험 요소

|자속 밀도|결과|
|---|---|
|**> 20 mT**|엔코더 **일시적 오작동**|
|**> 50 mT**|링 **영구 손상**|

X-Track은 AK 모터 4개가 근처에 있다. 영구자석 동기 모터의 누설 자속은 근접 시 수십 mT에 쉽게 도달한다.

**대책** (데이터시트 권장):

- 자기장을 발생원에서 차단
- 불가능하면 **강자성 금속판으로 차폐**
- 링 자체를 부분 차폐물로 활용 — **링의 바닥면을 누설 자기장 발생원 쪽으로 향하게 하고, 리드헤드는 반대쪽을 보게 설치**

취급 시에도 마그네틱 베이스 같은 강한 자석 근처에 두면 안 된다. 링 표면 50 mT 초과 노출은 영구 손상이다.

### 9.3 기타 환경

|항목|값|
|---|---|
|동작/보관 온도|−40 ~ +105 °C|
|습도|70% 이하, 비응결|
|충격|100 g (6 ms, 하프사인, EN 60068-2-27)|
|진동|80 g (55 Hz ~ 2000 Hz, EN 60068-2-6)|
|최대 속도 (사이즈 029)|10,000 rpm|
|링 재질 주의|링의 CPE 고무는 **대부분의 광유·그리스에 견디지 못함**|

마지막 항목이 UGV 환경에서 실질적 위험이다. 트랙 구동부 그리스가 링에 닿지 않도록 배치해야 한다.

리드헤드는 **ESD 민감** 부품이다. ESD 보호는 커넥터의 RS422 신호에만 적용(HBM Class 2, ±2 kV)되며 다른 부품은 만지면 안 된다.
