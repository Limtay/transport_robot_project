# Orbis UART(RS422) 인터페이스 — STM32 구현 규격서 & AksIM-2 대조

**대상 하드웨어**: RLS Orbis 보드레벨 리드헤드 `BR10` / `BR20` / `BR30` + BM 마그넷 또는 BA 마그네틱 액추에이터
**출처**: RLS 데이터시트 `BRD01_16` (Issue 16, 2026-05-08), p.7–9 / p.10–12 / p.15–16 / p.24–25 / p.30
**대조 대상**: `MBD01_15` (AksIM-2), 기존 문서 `aksim2_uart_rs422_stm32_guide.md`
**전제**: 통신 인터페이스 변형이 `SF`(Asynchronous serial, RS422)

> 두 엔코더 모두 RLS 제품이고 UART 프로토콜의 뼈대가 같아서 드라이버 재사용이 가능하다. 다만 **패킷 길이, 명령 세트, 분해능이 다르므로 파서는 분리해야 한다.** §1에 차이를 먼저 정리한다.

## 1. AksIM-2 대비 핵심 차이 요약

| 반경 변위 공차 | ±0.3 mm (MB029) | **±0.5 mm** | 관대 |
| **외부 자기장 한계** | 20 mT 오작동 / 50 mT 손상 | **±10 mT (DC)** | **Orbis가 2배 더 민감** |
| 소비 전류 | 130 mA typ | **65 mA typ** | 절반 |
| 커넥터 | 8핀 FCI/AMP 10114830 | **11핀 Molex 501568-1107** | 케이블 비호환 |
| 위치 갱신율 | 18 kHz 샘플링 / 9 kHz 대역폭 | **50 kHz 위치 갱신** | — |

| 자가 캘리브레이션 시간 | 기본 10초, 최대 40초 설정 가능 | **최대 10초 고정** | — |

### 1.2 설계 판단에 직결되는 세 가지

**(1) 정확도 격차가 크다.** Orbis BR10이 ±0.25°, AksIM-2 + MRA029가 ±0.014°다. 18배 차이. AS5600(12비트)과 비교하면 Orbis는 분해능 4배·정확도 개선이지만, AksIM-2급 정밀도를 기대하고 대체하면 안 된다. **X-Track에서 정밀도 병목인 관절에는 Orbis가 부족할 수 있다.**

**(2) 외부 자기장 한계가 오히려 더 낮다.** AksIM-2는 20 mT에서 일시 오작동인데, Orbis는 리드헤드 상단 기준 **±10 mT(DC)가 최대**이고 그 이상에서 정확도가 저하된다고 명시돼 있다. AK 모터 근처 배치라면 Orbis 쪽이 차폐 요구가 더 빡세다. 다만 Orbis 데이터시트는 축방향 성분이 덜 치명적이라고 밝히고 있으니, 리드헤드 평면을 모터 자속에 대해 어떻게 배향하느냐로 완화 여지가 있다.

**(3) 설치는 훨씬 쉽다.** AksIM-2는 라이드 하이트 0.05–0.35 mm를 맞춰야 해서 심(shim)까지 동원해야 하는데, Orbis는 마그넷 ID에 따라 4–6.5 mm ± 1 mm다. **±1 mm 공차면 일반 가공으로 충분하다.** 조립 난이도와 수율 측면에서 Orbis가 압도적으로 유리하고, 이게 실제 제품명의 "Wide installation tolerances" 문구가 의미하는 바다.

### 1.3 펌웨어에 미치는 영향

| 재사용 가능 | 재작성 필요 |
|---|---|
| USART 초기화 (8N1, 보드레이트) | 위치 파싱 함수 (2B vs 3B) |
| RS422 트랜시버 결선 개념 | 명령 디스패치 테이블 |
| IDLE + DMA 프레이밍 구조 | 상태 비트 해석 (1B vs 2B) |
| 타임스탬프 캡처 전략 | 온도 파싱 (×10 스케일) |
| 타당성 검사 프레임워크 | 부팅 시퀀스 (파트넘버 조회 불가) |

## 2. 인터페이스 개요

### 2.1 물리 계층

비동기 시리얼 통신은 UART로 알려진 범용 비동기 송수신기가 지원하며, **두 개의 단방향 채널이 전이중 양방향 데이터 링크**를 구성한다. 각 채널은 RS422 신호 규격을 따르는 2선 차동 트위스티드 페어다.

AksIM-2와 동일한 구조다. **DE/RE 방향 제어 불필요**, 전이중 트랜시버 사용, 엔코더 1개당 USART 1채널 전용.

```
        STM32                          Orbis (BR__)
    ┌───────────┐                     ┌──────────────┐
    │  USART_TX ├──► [RS422 Driver] ══╪══► RX+ / RX-  │   (핀 7/8)
    │  USART_RX ◄── [RS422 Receiver]══╪══ TX+ / TX-  │   (핀 10/11)
    └───────────┘                     └──────────────┘
```

RX 신호는 엔코더 내부에서 **RC(100 Ω, 1 nF) 종단**되어 있다. AksIM-2는 종단값을 명시하지 않았는데 Orbis는 구체적으로 밝혀놨다.

### 2.2 통신 파라미터 (p.15)

| 항목 | 값 | AksIM-2 대비 |
|---|---|---|
| Character length | 8 bits | 동일 |
| Parity | **None** | 동일 |
| Stop bits | **1** | 동일 |
| Flow control | **None** | 동일 |
| Bit order | **LSB first (standard)** | 동일 (AksIM은 "big-endian order" 문구 추가) |
| 프레임 형식 | **8N1** | 동일 |

> **바이트 순서 주의**: Orbis 데이터시트는 "LSB first (standard)"만 적고 big-endian을 명시하지 않았지만, 위치 데이터 구조가 "Left aligned, **MSB first**"라고 되어 있다. 즉 **멀티바이트 값은 MSB 바이트가 먼저 온다** — AksIM-2와 동일하게 시프트+OR로 조립해야 하고 `memcpy` 캐스팅은 금지다.

### 2.3 보드레이트 (p.15)

| 변형 | A | B | C | D | E | F |
|---|---|---|---|---|---|---|
| kbps | 115.2 | 128 | 230.4 | 256 | 500 | **1,000** |

**AksIM-2에 있던 G(921.6 kbps)가 없다.** 6종뿐이므로 보드레이트 스윕 시 후보가 하나 줄어든다.

F446 APB1 42 MHz 기준 오차:

| 변형 | 목표 | 실제 | 오차 |
|---|---|---|---|
| F | 1,000,000 | 1,000,000 | **0.00%** |
| E | 500,000 | 500,000 | **0.00%** |
| D | 256,000 | 256,098 | +0.04% |
| C | 230,400 | 230,769 | +0.16% |
| B | 128,000 | 128,049 | +0.04% |
| A | 115,200 | 115,068 | −0.11% |

E와 F가 정수로 떨어진다. 발주 시 선택권이 있으면 **F 변형** 권장.

## 3. 전기적 연결

### 3.1 핀맵 (p.10, p.30) — **11핀, AksIM-2와 완전히 다름**

| 커넥터 핀 | DSUB-9 | 케이블 색 | SF (비동기 시리얼) |
|---|---|---|---|
| **1** | 5 | 갈색 | **Vdd (5 V)** |
| **2** | – | – | Vdd (PCB 내부에서 핀1과 연결) |
| **3** | 9 | 흰색 | **GND (0 V)** |
| **4** | – | – | GND (PCB 내부에서 핀3과 연결) |
| 5 | 8 | 분홍 | 미사용 |
| 6 | 4 | 회색 | 미사용 |
| **7** | 2 | 빨강 | **RX command in +** |
| **8** | 3 | 파랑 | **RX command in −** |
| **9** | 1 | – | **Cable shield** |
| **10** | 6 | 초록 | **TX data out +** |
| **11** | 7 | 노랑 | **TX data out −** |

주요 차이:
- **핀 수가 8 → 11개.** 커넥터는 **Molex 501568-1107** (AksIM-2는 FCI/AMP 10114830-11108LF). **케이블 호환 안 됨.**
- 짝 커넥터: **Molex 501330-1100**(하우징) + **501334-0000**(터미널)
- 전원/GND가 각 2핀씩 중복(내부 연결). 전류 용량 여유
- **케이블 실드 전용 핀(9번)이 있다.** AksIM-2는 실드가 커넥터 핀에 할당되지 않았음
- **외부 온도센서 패스스루가 없다.** AksIM-2의 3/4번 핀 기능 없음
- 신호 색상 매핑은 우연히 AksIM-2와 동일 (빨강=클럭/명령+, 파랑=−, 초록=데이터+, 노랑=−)

커넥터 옵션 `H`를 선택하면 커넥터 대신 **스루홀 납땜 패드**가 나온다 (AksIM-2의 `P` 옵션에 해당).

### 3.2 전원 (p.9)

| 항목 | Orbis | AksIM-2 |
|---|---|---|
| 공급 전압 | 4.5 – 5.5 V (커넥터 기준) | 동일 |
| Set-up time | 100 ms (최악 200 ms) | 동일 |
| 소비 전류 | **typ 65 mA** (무부하) | typ 130 mA |
| 출력 부하 (RS422) | **max ±100 mA at 5 V** | ±40 mA |
| ESD 보호 | HBM max ±2 kV | HBM Class 2, ±2 kV |

**상승 시간 20 ms 제약이 Orbis 데이터시트에는 명시되지 않았다.** AksIM-2에서 요구하던 항목인데 여기엔 없다. 전원 설계 시 굳이 완화할 이유는 없으니 동일하게 20 ms 이내로 맞추는 걸 권한다.

펌웨어는 **전원 인가 후 최소 200 ms 대기** 후 첫 요청. AksIM-2와 동일.

### 3.3 케이블 (p.29)

`H`가 아닌 `D`(커넥터) 옵션 리드헤드용:

| 품번 | 길이 | 반대쪽 | 외경 | 온도 |
|---|---|---|---|---|
| **ACC048** | 1.0 m | 플라잉 리드 | 6.2 mm | −40 ~ +75 °C |
| **ACC067** | 1.0 m | DSUB-9 M | 6.2 mm | −40 ~ +75 °C |
| **ACC066** | 3.0 m | 플라잉 리드 | 6.2 mm | −40 ~ +75 °C |
| ACC012 / ACC027 / ACC024 | 1.0 / 1.0 / 3.0 m | — | 5 mm | −30 ~ +100 °C |

- 전부 4 × 2 × 0.14 mm² 트위스티드 페어 + 실드
- **ACC012, ACC024, ACC027은 단종 예정**이므로 6.2 mm 계열(048/066/067)로 갈 것
- `ACC067`은 E201-9S / E201-9B USB 인터페이스에 직결 가능

## 4. 명령 세트 (p.16)

### 4.1 명령 일람 — **AksIM-2의 5/9만 존재**

괄호 안은 멀티턴(`14M`) 옵션일 때.

| 명령 | HEX | 총 응답 길이 (싱글턴 / 멀티턴) | 응답 구성 |
|---|---|---|---|
| `'1'` | 0x31 | 3 / 5 B | 헤더 `'1'` + 위치 2(4) B |
| `'3'` | 0x33 | **2 / 4 B** | 위치 2(4) B **만** (헤더 없음) |
| `'d'` | 0x64 | 4 / 6 B | 헤더 `'d'` + 위치 2(4) B + 상세 상태 **1 B** |
| `'t'` | 0x74 | 5 / 7 B | 헤더 `'t'` + 위치 2(4) B + 온도 **2 B** |
| `'v'` | 0x76 | **7 B** | 헤더 `'v'` + ASCII 시리얼 **6 B** |

### 4.2 없어진 명령 — 진단 능력 손실

| 명령 | AksIM-2 기능 | Orbis UART |
|---|---|---|
| `'j'` | 영속 상세 상태 (누적 에러) | **없음** |
| `'s'` | 회전 속도 (RPM) | **없음** |
| `'a'` | 신호 레벨 → 라이드 하이트 환산 | **없음** (SPI에만 존재) |
| `'i'` | 자가 캘리브레이션 상태, 링 편심 | **없음** (SPI에만 존재) |

**이게 UART 변형 선택의 가장 큰 대가다.** 특히:

- **`'j'` 부재** → 간헐적 에러를 사후 추적할 수단이 없다. AksIM 가이드 §6.3의 "방어책 4(주기적 `'j'` 폴링)"를 Orbis에서는 쓸 수 없고, 대신 STM32에서 `'d'` 결과를 직접 누적(OR 축적)해야 한다.
- **`'a'` 부재** → 조립 후 에어갭을 정량 검증할 수 없다. LED 색상과 `'d'`의 b7/b6 비트로 정성 판단만 가능.
- **`'s'` 부재** → 속도는 위치 수치 미분으로 직접 구해야 한다. 14비트 분해능에 디지털 히스테리시스 ±2 LSB라 미분 노이즈가 AksIM보다 불리하다.

> 참고: Orbis **SPI 변형**에는 `'a'`(신호 레벨), `'i'`(자가 캘리브레이션 결과), `'f'`(펌웨어 버전), `'p'`(파트넘버 16자) 명령이 있다. 진단 기능이 중요하면 SPI 변형이 UART보다 유리하다 — AksIM-2에서는 반대였던 관계가 뒤집힌다.

### 4.3 `'v'` 응답이 6바이트뿐 — 런타임 자동 인식 불가

AksIM-2 가이드에서는 `'v'`가 58바이트를 돌려주고 그 안 B19–B34에 파트넘버 16자가 들어 있어서, 부팅 시 파트넘버를 읽어 파서를 런타임 선택하는 구조를 권장했다.

**Orbis UART의 `'v'`는 ASCII 시리얼 넘버 6바이트만 돌려준다.** 파트넘버, 펌웨어 버전, 분해능 정보가 전부 없다.

결과:
- **분해능(14B/14M)과 보드레이트 변형을 펌웨어에 하드코딩하거나 설정으로 넣어야 한다**
- 하드웨어 교체 시 펌웨어 수정 또는 설정 변경이 필요
- 파트넘버는 라벨 확인 또는 SPI 변형의 `'p'` 명령으로만 확보 가능

싱글턴/멀티턴 자동 판별은 응답 길이로 간접 추정할 수 있다. `'3'` 발행 후 IDLE까지 2바이트가 오면 `14B`, 4바이트면 `14M`. 부팅 시 1회 실행하는 프로브로 쓸 만하다.

### 4.4 200 Hz 루프에서의 선택

`'3'`이 최선인 건 동일. **왕복 3바이트(TX 1 + RX 2)로 AksIM보다 1바이트 짧다.**

상세 상태는 저주기(10 Hz)로 `'d'`를 끼워 넣되, `'j'`가 없으므로 **STM32에서 상태 비트를 OR 누적**해서 영속 상태를 소프트웨어로 구현할 것.

## 5. 위치 데이터 패킷 구조 (p.16)

### 5.1 싱글턴 `14B` — 2바이트 (16비트)

```
b15 ─────────────────── b2 │ b1 │ b0
      Encoder position 14b  │ E  │ W
```

| 필드 | 비트 | 설명 |
|---|---|---|
| Encoder position | **b15 : b2** | 14비트, 좌측 정렬, MSB first |
| Error | **b1** | **Low면 위치 무효.** 마지막 유효 위치가 전송됨 |
| Warning | **b0** | Low면 위치는 유효하나 동작 한계 근접 |

**AksIM-2와의 결정적 차이: 0 패딩 비트가 없다.** AksIM은 분해능이 17~20비트로 가변이라 24비트 필드에 패딩이 들어갔지만, Orbis는 14 + 2 = 16비트로 정확히 채워진다. 파싱이 단순하고 분해능별 분기가 불필요하다.

에러/워닝은 **active low**로 AksIM-2와 동일. 에러 시 마지막 유효값이 그대로 나오는 것도 동일하며, 값이 멈춰 보이는 증상을 스케일 버그로 오진하지 않도록 주의.

> **교차 인터페이스 주의**: Orbis 데이터시트의 SSI 섹션(p.20)은 b9/b8을 "**If high**, position data is not valid"로 기술한다. UART/BiSS/SPI는 active low인데 SSI만 반대다. UART 드라이버만 쓴다면 무관하지만, 나중에 인터페이스를 바꾸면 극성이 뒤집힌다.

### 5.2 멀티턴 `14M` — 4바이트 (32비트)

```
b31 ─────── b16 │ b15 ─────── b2 │ b1 │ b0
  멀티턴 16b     │  싱글턴 위치 14b │ E  │ W
```

| 필드 | 비트 | 설명 |
|---|---|---|
| Multiturn counter | **b31 : b16** | 16비트 (0–65535), 좌측 정렬, MSB first |
| Encoder position | **b15 : b2** | 14비트 |
| Error / Warning | b1 / b0 | active low |

### 5.3 파싱 코드 (C)

```c
#include <stdint.h>

#define ORBIS_BITS        14u
#define ORBIS_COUNTS      (1u << ORBIS_BITS)              /* 16384 */
#define ORBIS_DEG_PER_CNT (360.0f / (float)ORBIS_COUNTS)  /* ≈ 0.021973° */

typedef struct {
    uint16_t position;      /* 0 .. 16383 */
    uint16_t multiturn;     /* 14M 변형에서만 유효 */
    uint8_t  error;         /* 1 = 에러 (원본 active-low를 반전 저장) */
    uint8_t  warning;       /* 1 = 워닝 */
} Orbis_Position_t;

/* ---- 14B 싱글턴 (2바이트) ---- */
static inline void Orbis_Parse14B(const uint8_t *rx, Orbis_Position_t *out)
{
    uint16_t raw = ((uint16_t)rx[0] << 8) | (uint16_t)rx[1];   /* rx[0]이 MSB */

    out->position  = (uint16_t)((raw >> 2) & 0x3FFFu);   /* b15..b2 */
    out->error     = ((raw >> 1) & 1u) ? 0u : 1u;        /* active low 반전 */
    out->warning   = ((raw >> 0) & 1u) ? 0u : 1u;
    out->multiturn = 0;
}

/* ---- 14M 멀티턴 (4바이트) ---- */
static inline void Orbis_Parse14M(const uint8_t *rx, Orbis_Position_t *out)
{
    uint32_t raw = ((uint32_t)rx[0] << 24)
                 | ((uint32_t)rx[1] << 16)
                 | ((uint32_t)rx[2] <<  8)
                 |  (uint32_t)rx[3];

    out->multiturn = (uint16_t)((raw >> 16) & 0xFFFFu);  /* b31..b16 */
    out->position  = (uint16_t)((raw >>  2) & 0x3FFFu);  /* b15..b2  */
    out->error     = ((raw >> 1) & 1u) ? 0u : 1u;
    out->warning   = ((raw >> 0) & 1u) ? 0u : 1u;
}

/* ---- 각도 변환 ---- */
static inline float Orbis_AngleDeg(uint16_t position)
{
    return (float)position * ORBIS_DEG_PER_CNT;
}
```

### 5.4 분해능 vs 정확도 — Orbis에서 더 중요한 구분

| 항목 | BR10 | BR20 | BR30 |
|---|---|---|---|
| 분해능 | 14 bit (16,384 counts) | 동일 | 동일 |
| 1 count | 0.021973° | 동일 | 동일 |
| **시스템 정확도** | **±0.25°** | **±0.3°** | **±0.5°** |
| 반복도 | ±2 LSB (≈ ±0.044°) | 동일 | 동일 |
| 디지털 히스테리시스 | ±2 LSB | 동일 | 동일 |
| 열 드리프트 | ±0.003 °/°C | 동일 | 동일 |

**BR10 기준 정확도 ±0.25°는 1 count의 약 11배다.** 절대 각도 오차 예산에는 반드시 정확도 값을 쓸 것. 분해능은 미분(속도 추정)과 제어 루프의 부드러움에만 유효하다.

열 드리프트 ±0.003 °/°C도 무시하기 어렵다. −40 ~ +105 °C 전 범위에서 최대 약 ±0.22°가 추가되므로, 실외 UGV라면 정확도와 같은 급의 오차원이다. AksIM-2는 열 드리프트가 없다(정확도가 온도에 따라 변하지 않음)고 명시돼 있어 이 항목에서도 차이가 난다.

Orbis에는 **적응형 필터링**이 내장되어 저속에서 고분해능을, 고속에서 낮은 각도 위상 지연을 제공한다. 저속 구간의 노이즈가 자동으로 억제되므로 AksIM-2보다 원시값을 그대로 쓰기 수월한 면이 있다.

## 6. 부가 데이터 패킷

### 6.1 `'d'` — 상세 상태 **1바이트** (p.16)

응답: `['d'][pos 2B or 4B][status]`

| 비트 | 의미 |
|---|---|
| **b7** | Warning: 라이드 하이트 하한 공차 도달 / Error: 신호 진폭 과대. 리드헤드가 마그넷에 너무 가깝거나 외부 자기장이 존재하고 과대함 |
| **b6** | Warning: 라이드 하이트 상한 공차 도달 / Error: 신호 진폭 과소. 리드헤드-링 거리 과대 |
| **b5** | Warning: 리드헤드 온도 규격 이탈 |
| **b4** | Warning: 속도 과대 |
| **b3** | Error: 멀티턴 카운터 오류 |
| b2 : b0 | Reserved |

**b7/b6이 이중 의미를 갖는 게 함정이다.** 같은 비트가 "워닝: 공차 한계 도달"일 수도 "에러: 진폭 이상"일 수도 있다. 어느 쪽인지는 **위치 패킷의 General status(b1 에러 / b0 워닝)로 판별**해야 한다.

```c
typedef enum { ORB_OK, ORB_WARN, ORB_ERR } OrbisSeverity_t;

/* 위치 패킷의 E/W 비트로 b7/b6의 의미를 확정 */
static OrbisSeverity_t Orbis_RideHeightSeverity(const Orbis_Position_t *p,
                                                uint8_t status, uint8_t bit)
{
    if (!((status >> bit) & 1u)) { return ORB_OK; }
    return p->error ? ORB_ERR : ORB_WARN;
}
```

AksIM-2의 2바이트 상세 상태에 있던 항목 중 Orbis에 **없는 것**: 센서 판독 오류(전기적 간섭/그라운드 루프/RFI), 전원 공급 오류, 시스템 오류, 자기 패턴 오류, 가속도 오류, 설정 부적절. 진단 해상도가 확실히 낮다.

### 6.2 `'j'`가 없으므로 소프트웨어로 영속 상태 구현

```c
static uint8_t g_orbis_persistent = 0;   /* 상세 상태 누적 */
static uint8_t g_orbis_persist_err = 0;  /* 에러 발생 이력 */

void Orbis_AccumulateStatus(const Orbis_Position_t *p, uint8_t status)
{
    g_orbis_persistent |= status;
    if (p->error) { g_orbis_persist_err = 1; }
}

void Orbis_ClearPersistent(void)
{
    g_orbis_persistent = 0;
    g_orbis_persist_err = 0;
}
```

`'d'`를 10 Hz로 폴링하면서 이 함수를 호출하면 AksIM-2의 `'j'`에 준하는 기능이 된다. 다만 폴링 주기보다 짧은 이벤트는 놓치므로, 엔코더 하드웨어가 잡아주던 것과 완전히 등가는 아니다.

### 6.3 `'t'` — 온도 **2바이트, ×10 스케일**

응답: `['t'][pos 2B or 4B][temp_hi][temp_lo]`

**16비트 부호 있는 값이며, 리드헤드 온도(°C)에 10을 곱한 수치다.**

- 주변 온도보다 통상 **10 ~ 15 °C 높게** 나옴 (AksIM-2는 5 ~ 15 °C)
- 판독 공차 **±5 °C**

```c
static inline float Orbis_ParseTemp(const uint8_t *p)
{
    int16_t t10 = (int16_t)(((uint16_t)p[0] << 8) | (uint16_t)p[1]);
    return (float)t10 / 10.0f;   /* °C */
}
```

AksIM-2는 1바이트 정수 °C였다. **파싱 코드를 그대로 가져오면 값이 10배로 나온다.** 이식 시 가장 흔히 놓칠 지점.

### 6.4 `'v'` — 시리얼 넘버 7바이트

응답: `['v'][s0][s1][s2][s3][s4][s5]`

```c
static void Orbis_ParseSerial(const uint8_t *rx, char *out /* [7] */)
{
    memcpy(out, &rx[1], 6);
    out[6] = '\0';
}
```

통신 링크 확인(응답 오면 링크 정상) 및 개체 식별용으로만 쓸 수 있다. 파트넘버·펌웨어 버전은 UART로 조회 불가.

## 7. STM32 구현 설계

### 7.1 타이밍 예산 (8N1, 바이트당 10비트)

| 보드레이트 | 바이트/µs | `'3'` (1TX+2RX=3B) | `'d'` (1TX+3RX=4B) | `'t'` (1TX+5RX=6B) |
|---|---|---|---|---|
| 115.2 k | 86.8 | 260 µs | 347 µs | 521 µs |
| 128 k | 78.1 | 234 µs | 313 µs | 469 µs |
| 230.4 k | 43.4 | 130 µs | 174 µs | 260 µs |
| 256 k | 39.1 | 117 µs | 156 µs | 234 µs |
| 500 k | 20.0 | 60 µs | 80 µs | 120 µs |
| **1 M** | **10.0** | **30 µs** | **40 µs** | **60 µs** |

싱글턴 기준. 멀티턴은 위치가 2 → 4바이트가 되므로 각각 +2 B.

**200 Hz 루프(5 ms)에서는 최저 보드레이트로도 여유가 크다.** AksIM-2 대비 패킷이 1바이트 짧아 약간 더 빠르다.

5채널 순차 폴링 시 115.2 k에서 1.3 ms, 1 M에서 150 µs. 5 ms 주기 안에 충분히 들어간다.

### 7.2 위치 래치 시점 — **데이터시트에 명시가 없다**

AksIM-2는 "위치가 명령 바이트의 첫 비트에서 래치되고 지연 < 10 µs"라고 못박아뒀는데, **Orbis UART 섹션에는 래치 시점과 지연 스펙이 없다.**

알 수 있는 것:
- 위치 갱신율 50 kHz → 내부 사이클 20 µs
- SPI 섹션에서는 "NCS를 Low로 설정하는 순간 마지막 가용 위치 데이터가 래치된다"고 기술
- PWM 섹션에서는 "PWM Out 상승엣지에서 래치"

UART에서 명령 수신 시점 래치인지, 최근 내부 사이클 값을 그대로 내보내는지 불명확하다. 보수적으로 보면 **최대 20 µs(내부 사이클 1주기)의 불확실성**을 가정해야 한다. delta_tick 100 µs LSB 대비 0.2 LSB이므로 실용상 무시 가능하지만, AksIM-2처럼 "<10 µs 보장"이라고 단정하지는 말 것.

타임스탬프는 동일하게 **명령 송신 시작 시각**에 캡처한다.

```c
uint32_t ts = __HAL_TIM_GET_COUNTER(&htim5);   /* 10 kHz free-running */
HAL_UART_Transmit(&huart_enc, &cmd, 1, 2);     /* 1바이트, 블로킹 OK */
```

정확한 래치 동작이 중요하면 앱노트 **BRD04**를 확인하거나 RLS에 문의할 것.

### 7.3 프레이밍 및 재동기화

AksIM-2와 동일하게 **위치 패킷 CRC가 없다.** 에러/워닝 비트 2개뿐이고 동기 바이트도 길이 필드도 없다.

> 참고: Orbis의 **BiSS C는 6비트 CRC(0x43)**, **SPI는 8비트 CRC(0x97)**를 제공한다. UART만 CRC가 없는 구조도 AksIM-2와 동일하다.

#### 방어책 1 — IDLE 라인 검출 기반 프레이밍

```c
#define ORBIS_RX_BUF   16
static uint8_t rx_buf[ORBIS_RX_BUF];
static uint8_t expected_len = 2;   /* '3' 싱글턴 */

void Orbis_IdleCallback(void)
{
    uint16_t received = ORBIS_RX_BUF - __HAL_DMA_GET_COUNTER(huart_enc.hdmarx);

    if (received == expected_len) {
        Orbis_Parse14B(rx_buf, &g_encoder);
        g_rx_ok++;
    } else {
        g_rx_framing_err++;
    }

    /* 매 트랜잭션마다 재무장 — 링버퍼 desync 원천 차단 */
    HAL_UART_AbortReceive(&huart_enc);
    HAL_UART_Receive_DMA(&huart_enc, rx_buf, ORBIS_RX_BUF);
}
```

#### 방어책 2 — 응답 타임아웃

`(예상 바이트 수 × 바이트 시간 × 2 + 100 µs)`. 200 Hz 루프에서 1 ms 정도. 연속 N회 실패 시 `LS_OFFLINE` 강등.

#### 방어책 3 — 위치 타당성 검사

**14비트라 AksIM-2보다 랩어라운드 여유가 훨씬 적다.** 16,384 counts에서 반 바퀴는 8,192 counts. 최대 속도 12,000 rpm = 200 rev/s에서 5 ms면 1 회전이므로, 고속 회전 시 전제가 완전히 깨진다.

```c
#define ORBIS_MAX_DELTA  ((uint16_t)(OMEGA_MAX_RPS * ORBIS_COUNTS * T_SAMPLE * 1.5f))

static uint16_t prev_pos;
static uint8_t  prev_valid = 0;

uint8_t Orbis_PlausibilityCheck(uint16_t pos)
{
    if (!prev_valid) { prev_pos = pos; prev_valid = 1; return 1; }

    int32_t d = (int32_t)pos - (int32_t)prev_pos;
    if (d >  (int32_t)(ORBIS_COUNTS/2)) { d -= (int32_t)ORBIS_COUNTS; }
    if (d < -(int32_t)(ORBIS_COUNTS/2)) { d += (int32_t)ORBIS_COUNTS; }

    if ((uint32_t)((d < 0) ? -d : d) > ORBIS_MAX_DELTA) {
        return 0;
    }
    prev_pos = pos;
    return 1;
}
```

**X-Track 4절 링크의 실제 각속도를 먼저 측정하고 `OMEGA_MAX_RPS`를 설정할 것.** 링크 회전이 초당 반 바퀴 이하라면 이 검사는 유효하고, 그 이상이면 검사를 포기하거나 샘플링을 올려야 한다.

#### 방어책 4 — 상태 비트 소프트웨어 누적

§6.2 참조. `'j'`가 없으므로 필수.

### 7.4 부팅 시퀀스 (권장)

```
1. 5V 인가 (상승시간 20 ms 이내 권장)
2. 200 ms 대기                          ← set-up time 최악값
3. 'v' 송신 → 7바이트 수신
   ├─ 응답 있으면 링크 정상, 시리얼 6자 로깅
   └─ 실패 시 보드레이트 스윕 (A~F, 6종)
4. '3' 송신 → IDLE까지 바이트 수 측정
   ├─ 2바이트 → 14B (싱글턴)
   └─ 4바이트 → 14M (멀티턴)
5. 'd' 송신 → 상세 상태 확인
   ├─ b7 셋 + 에러 → 마그넷에 너무 가까움 또는 외부 자기장 과대
   ├─ b6 셋 + 에러 → 거리 과대
   └─ 정상이면 진행
6. LED 육안 확인 (녹색 점등 = 정상)
7. LS_INIT → LS_RUNNING 승격
8. 200 Hz 루프에서 '3' 폴링 시작
```

AksIM-2 시퀀스와의 차이: **3단계에서 파트넘버를 얻을 수 없고**, `'a'`/`'i'`가 없어 **라이드 하이트·편심 정량 검증 단계가 통째로 빠진다.**

### 7.5 LED가 유일한 조립 검증 수단 (p.8, p.11)

`'a'` 명령이 없으므로 라이드 하이트 확인은 물리적 방법에 의존한다.

- 비자성·비전도성 공구로 기계적 확인
- **LED가 녹색으로 점등하고 마그넷 회전 중 색이 변하지 않으면 라이드 하이트 정상**

| LED | 상태 |
|---|---|
| 녹색 | 정상, 위치 유효 |
| 주황 | 워닝. 위치는 유효하나 분해능/정확도 규격 이탈 가능 |
| 적색 | 에러. 위치 무효 |
| 느린 점멸 | 통신 미확립 (200 ms 내 요청 없음) |
| 소등 | 전원 없음 |
| 빨강 연속 고속 점멸 | 시동/동작 중 시스템 오류 |
| 3초 고속 점멸 | 자가 캘리브레이션 결과 (BRD04 / BRD05 참조) |

**LED 듀티가 통신 상태를 알려준다.** 유휴 상태에서는 듀티 50%, 2.5 Hz로 점멸하고, 컨트롤러가 200 ms 이하 간격으로 데이터를 요청하면 듀티 100%(상시 점등)가 된다. 200 Hz 폴링 중이라면 LED가 계속 켜져 있어야 정상이며, 점멸이 보이면 폴링이 끊긴 것이다. **스코프 없이 통신 살아있음을 육안 확인할 수 있는 유용한 지표다.**

### 7.6 채널 배정

AksIM-2와 동일한 제약. F446은 USART 6채널이 상한이고, 엔코더 1개당 1채널 전용.

Orbis도 **SPI 변형(`SP`)이 존재**하며, NCS를 제외한 모든 라인을 공유해 다중 슬레이브를 병렬 연결할 수 있다고 데이터시트가 명시한다. 게다가 Orbis SPI는 UART에 없는 `'a'`, `'i'`, `'f'`, `'p'` 명령까지 제공하므로, **5채널 구성에서는 SPI 변형이 UART보다 명확히 우월하다.**

| 구성 | 채널 | 진단 명령 | CRC |
|---|---|---|---|
| Orbis UART × 5 | USART 5개 | `1 3 d t v` | 없음 |
| **Orbis SPI × 5** | **SPI 1개 + NCS 5개** | **`1 3 d t v a i f p`** | **8비트 (0x97)** |

Orbis에서는 SPI를 고르지 않을 이유가 거의 없다.

## 8. 자가 캘리브레이션 (p.8)

편심 기인 오차를 제거하며 1회전당 1개 사인파 오차를 없앤다. `DC`, `SP`, `SF` 인터페이스 또는 USB 인코더 인터페이스로 트리거 가능.

| 요구 조건 | Orbis | AksIM-2 |
|---|---|---|
| 자유 회전 | **1회전 전체 (360°) 필수** | 180° ~ 360° |
| 최대 소요 시간 | **10초 (고정)** | 기본 10초, 최대 40초 설정 |
| **최대 속도** | **600 RPM 이하** | (최소 6 RPM) |
| 방향 | 무관 | 무관 |
| 신호 품질 | 전체 각도에서 양호 | 동일 |
| 시작 조건 | **에러 없을 것 (녹색 LED)** | 경고·에러 없을 것 |

**Orbis는 360° 전체 회전이 필수**라 부분 회전만 가능한 기구에서는 캘리브레이션을 못 한다. X-Track 4절 링크가 제한 각도만 움직인다면 **조립 전 별도 지그에서 캘리브레이션을 수행**하고 장착해야 한다. AksIM-2는 180°만 돌아도 되므로 이 부분은 AksIM이 유연하다.

멀티턴 사용 시 ±300 RPM 초과하면 멀티턴 카운터가 틀어지고 에러 플래그가 셋되는 건 양쪽 동일.

SPI 변형에서는 자가 캘리브레이션 상태를 LED로 확인해야 한다고 명시돼 있다.

## 9. 멀티턴 카운터 (p.12)

**AksIM-2와 사실상 동일하다.** 16비트(0–65535), 전원 인가 중에만 카운팅, 전원 차단 시 비휘발성 저장 후 복원, **차단 중 허용 회전 ±90°**, ±360°나 정수배 회전은 등록되지 않음.

실패 조건과 대응도 동일:

| 실패 조건 | 대응 |
|---|---|
| 전원 차단 중 ±360° 이상 회전 | 기계식 브레이크 사용 |
| 90° 이상 회전 중 에러 플래그 존재 | 에러 비트 판독·평가 |
| 블로킹 동작 중 90° 이상 이동 또는 300 RPM 이상 | 해당 동작 전 회전 정지 |
| 싱글턴 위치 오프셋을 90° 이상 변경 | 오프셋 설정 직후 새 멀티턴 값 설정 |
| 비휘발성 저장 중 전원 차단 | 해당 동작 중 전원 안정 유지 |

멀티턴 에러 플래그 셋 조건: 전원 차단 중 >90° 且 <270° 이동, 블로킹 동작 중 300 RPM 초과, 예상치 못한 큰 위치 차이(가속도 오류).

### Orbis 고유 — 배터리 백업 멀티턴 (BBM)

**Orbis에만 있는 옵션이다.** 외부 배터리로 엔코더에 전원을 공급해 주 전원이 없을 때도 회전수 카운팅을 유지할 수 있다. 상세는 문서 **BRD08** 참조.

X-Track처럼 전원 차단 중 자중이나 외력으로 링크가 움직일 수 있는 구조에서는 이게 실질적 해법이 될 수 있다. AksIM-2에서 권장했던 "부팅 시 멀티턴 프리셋" 우회책 없이도 절대 위치를 유지할 수 있다.

그래도 **1회전 미만 범위라면 싱글턴(`14B`)이 여전히 정답이다.**

## 10. 설치 및 환경 제약

### 10.1 설치 공차 (p.7) — Orbis의 최대 강점

| 항목 | Orbis | AksIM-2 (MB029) |
|---|---|---|
| **축방향 (ΔZ, 라이드 하이트)** | 마그넷 ID별 아래 표 | **0.05 – 0.35 mm** |
| 반경방향 (ΔR) 센서 변위 | **최대 0.5 mm** | ±0.3 mm |
| 리드헤드 직각도 | **1°** | 0.2° (틸트) |
| 마그넷 직각도 | **2°** | — |

라이드 하이트 (마그넷 ID 기준):

| 마그넷 ID | 라이드 하이트 |
|---|---|
| 12 mm | **4 mm ± 1 mm** |
| 16 mm | **5.5 mm ± 1 mm** |
| 22 mm | **6.5 mm ± 1 mm** |
| 30 mm | **4 mm ± 1 mm** |

**±1 mm 공차는 AksIM-2의 ±0.15 mm 대비 6배 이상 관대하다.** 심 조정이 불필요하고, 일반 가공·조립 공차로 충분히 들어간다. 조립 수율과 재현성 측면에서 Orbis의 가장 큰 실무적 이점이다.

### 10.2 외부 자기장 — **Orbis가 더 취약** (p.8, p.9)

| 항목 | Orbis | AksIM-2 |
|---|---|---|
| 최대 허용 | **±10 mT (DC), 리드헤드 상단 기준** | 20 mT 오작동 / 50 mT 영구 손상 |
| 영향 | 정확도 저하 | 오작동 / 링 손상 |
| 방향 민감도 | **반경·축방향 모두 영향, 축방향이 덜 치명적** | 명시 없음 |

**이게 X-Track에서 가장 주의할 항목이다.** AK 모터 4개가 근처에 있는 환경에서 Orbis는 AksIM-2보다 2배 낮은 자기장에서 정확도가 나빠진다. 게다가 이미 정확도가 ±0.25°로 여유가 적어서, 여기서 더 저하되면 AS5600 대비 이점이 사라질 수 있다.

대책:
- **리드헤드 평면을 모터 자속의 축방향 성분과 정렬**시키면 완화된다 (축방향이 덜 치명적)
- 강자성 차폐판
- 실측 필수 — 가우스미터로 설치 위치의 자속 밀도를 확인하고 10 mT 이하 확보

### 10.3 마그넷 장착 (p.6, p.7)

**이 데이터시트가 명확히 경고하는 항목**: 스펙은 마그넷이 **비철(non-ferrous) 샤프트**에 장착됐을 때 유효하다. 철제 샤프트를 쓰면 성능에 영향이 있으며, 이 경우 마그넷이 철 재료와 직접 접촉하지 않도록 **액추에이터 사용을 권장**한다.

X-Track 링크가 강철이라면 **BA 시리즈 마그네틱 액추에이터(양극산화 알루미늄)를 반드시 쓸 것.** 액추에이터 샤프트 공차 권장은 g6.

접착 장착 시:
- Loctite EA 9514
- 알코올로 샤프트·링 접촉면 세척 (먼지·오일·그리스 제거)
- 마그넷 전체 둘레에 균일 도포
- **최대 130 °C에서 45분 경화**
- 샤프트 OD = 공칭 마그넷 ID (−0.08 / −0.05)

체결 방식은 리드헤드 3× M2 DIN 912, 액추에이터 3× M3 DIN 913(포함). **리드헤드는 마운팅 홀 주변 금도금 면에만 접촉**시켜야 한다.

### 10.4 환경 (p.9)

| 항목 | Orbis | AksIM-2 |
|---|---|---|
| 동작/보관 온도 | −40 ~ +105 °C | 동일 |
| 습도 | 0 ~ 70% 비응결 | 70% 이하 비응결 |
| 충격 | 100 G (6 ms, EN 60068-2-27) | 100 g |
| **진동** | **40 G (55–2000 Hz)** | **80 g** |
| 최대 속도 | 12,000 rpm | 10,000 rpm (size 029) |

**진동 내성이 절반이다.** 트랙형 UGV의 진동 환경에서는 이 차이를 고려해야 한다. 40 G가 부족한 수치는 아니지만, 마운팅 강성과 케이블 스트레인 릴리프에 더 신경 쓸 필요가 있다.

커넥터 없는(`H`, 납땜 패드) 버전은 **납땜 전 보관 온도가 +15 ~ +30 °C, 습도 10% 이하**로 제한된다. 납땜 후에는 −40 ~ +105 °C / 70%로 완화. 재고 보관 시 주의.

리드헤드는 **ESD 민감** 부품.

## 11. 파트 넘버링 (p.24)

```
BR   10   SF   A   14B   16   D   D   00
│    │    │    │    │     │    │   │   └ 특수 요구사항 (00 = 없음)
│    │    │    │    │     │    │   └ 커넥터 (D = Molex 501568-1107 / H = 스루홀 납땜패드)
│    │    │    │    │     │    └ 동작 온도 (D = −40 ~ +105 °C)
│    │    │    │    │     └ 마그넷 호환 (12 / 16 / 22 / 30)
│    │    │    │    └ 분해능 (14B = 14비트 / 14M = 14비트 + 16비트 멀티턴)
│    │    │    └ 통신 변형 (SF일 때 A~F 링크 속도)
│    │    └ 통신 인터페이스 (DC / PW / SC / SF / SP)
│    └ 사이즈 (10 / 20 / 30)
└ 시리즈 (BR = Orbis 보드레벨 리드헤드)
```

AksIM-2(9필드)보다 1필드 적은 **8필드**이고, 분해능 필드가 `14B`/`14M` 두 가지뿐이다.

| 사이즈 | 샤프트 직경 | 마그넷 호환 | 정확도 |
|---|---|---|---|
| **BR10** | ~15 mm | 12 / 16 | ±0.25° |
| **BR20** | ~22 mm | 22 | ±0.3° |
| **BR30** | ~30 mm | 30 | ±0.5° |

**작은 사이즈일수록 정확하다** — AksIM-2는 링이 클수록 정확했던 것과 정반대 경향이다. AksIM은 MRA080이 ±0.004°로 가장 좋고 MRA022가 ±0.020°로 가장 나빴다. 사이즈 선정 시 이 반전을 기억할 것.

마그넷 파트넘버: `BM120A190A1ABA00`(12mm ID) / `BM160B240A1ABA00`(16) / `BM220C320A1ABA00`(22) / `BM300C440B1BBA00`(30)
액추에이터: `BA060`~`BA240` (샤프트 6/8/10/12/14/15/20/24 mm)
