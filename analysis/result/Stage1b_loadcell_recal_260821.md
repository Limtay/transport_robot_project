# Stage 1b — 앰프 span 조절 후 로드셀 재캘리브레이션 (2026-08-21)

> 트랙션 테스트베드 로드셀(ch0) 앰프의 **span/offset 을 손댄 뒤** cnt↔N 상수를 다시 잡았다.
> 선형성은 [[Stage1_loadcell_calibration_260721]] 에서 이미 46점·R²=0.999988 로 확증됐으므로
> **직선의 기울기·절편만** 다시 잡는 간이 절차(무게추 2개, 1사이클)로 진행했다.
> 분석 도구: `analysis/tools/loadcell_recal_quick.py`.

---

## 1. 최종 결과 (요약)

$$\text{Force[N]} = \frac{\text{cnt} - 10.08}{14.6934} \qquad (0.068058\ \text{N/cnt})$$

| 지표 | **이번 (08-21)** | 이전 (07-21) | 비고 |
|------|------------------|--------------|------|
| **감도 k** | **14.6934 cnt/N** | 12.6270 cnt/N | **span 1.164×** |
| **N/cnt** | **0.068058** | 0.079196 | |
| **offset** | **10.08 cnt** | 214.61 cnt | -204 cnt (조정 안 함 — §4.1) |
| 선형성 R² | 0.99999934 | 0.9999882 | 5점 / 46점 (점 수가 다르니 직접 비교는 무의미) |
| 피팅 잔차 | std 0.90 cnt = **±0.061 N** | 3.0 cnt = ±0.24 N | |
| 노이즈 (plateau std) | 1.47 cnt = **±0.100 N** | ~1.2 cnt = ±0.10 N | 힘 단위로는 동등 |
| 히스테리시스 | **+0.005 N** | 최대 0.17 N | 상행/하행 10.22 kg |
| 영점 복귀 | **+0.124 N** | — | 사이클 전후 무부하 차 |
| **확인된 선형 구간** | **0 ~ 200.7 N** | 0 ~ 229 N | 이번엔 20.47 kg 까지만 걸었다 |
| 포화 천장 | **미검증** (§4.2) | ~3234 cnt @ 247 N | |

이 상수는 `analysis/loadcell_cal.json` 에 **반영 완료**다 (§6).

![[stage1b_span_recal_260821.png]]

**span 을 올린 것은 의도대로 작동했다** — 잔차가 ±0.24 N → ±0.061 N 으로 4배 좋아졌다.
다만 힘 환산 노이즈(±0.100 N)는 이전과 같다. 즉 개선된 것은 **양자화/피팅 정밀도**이고
센서·기구계의 실제 노이즈 바닥은 그대로다.

## 2. 방법

- **방식**: 중력-저울 (무게추를 ch0 감지축에 중력방향 적재). ⚠ 이전과 같은 수직 근사.
- **무게추**: 10.22 kg(1번) + 10.25 kg(2번).
- **사이클 1회**: `무부하 → 1번 → 1번+2번 → 1번 → 무부하` (5단계).
  상행·하행이 10.22 kg 에서 겹치므로 **히스테리시스**가, 무부하가 앞뒤로 있으므로
  **영점 복귀**가 같은 사이클에서 나온다.
- **기록**: 브리지 `./run.sh traction` (= `bridge_mode:=control auto_mode:=none
  read_preset:=control_test`, READ 전용·무모터), `/carrier/control/feedback` **200 Hz** 라이브 로깅.
  각 단계 ≥10 s 유지 후 **마지막 5 s(1001샘플) 평균**.
- **피팅**: 5점 최소자승 `cnt = k·F + b` (F = kgf × 9.80665).

> 구 절차와 달라진 점: `traction_test_mode` 불리언은 폐지됐고 토픽도
> `/carrier/testbed/feedback` → `/carrier/control/feedback` 으로 개명됐다. 구 문서의
> 명령을 그대로 쓰면 브리지가 기동 게이트에서 거부하거나 **빈 bag** 이 된다.

## 4. 핵심 발견 — 결정 하나, 미확인 하나

### 4.1 무부하 영점이 ADC 바닥에 붙어 있다 — **조정하지 않기로 결정**

무부하 ch0 이 **8.8 cnt** 다. 도구의 게이트 두 개를 모두 위반한다:

| 게이트 | 값 | 현재 | 판정 |
|--------|-----|------|------|
| `ZERO_MIN_CNT` (무부하 하한, test_plan Stage 1) | 300 cnt | 8.8 | **위반** |
| `RAIL_LOW` (이 밑은 단선 오검출 위험) | 8 cnt | 8.8 | **경계 위** |

즉 `loadcell_calib.py --zero` 판정은 **실패한다** — 이 캘리에서는 정상이다. 함의:

- 힘이 **음(-)방향으로 0.69 N** 만 가도 클리핑돼 못 읽는다.
- tare(baseline 차감) 방식이라 **절대 힘 계산 자체는 offset 과 무관**하지만, 클리핑된
  구간은 복구할 방법이 없다 — 조용히 0 으로 눌린 데이터가 남는다.

**결정 (2026-08-21): offset trim 을 조정하지 않고 그대로 간다.** 견인력은 단방향(양의 힘)
이므로 음방향 여유를 설계 전제에서 제외한다. 그 대신 위쪽 여유를 최대로 쓴다 (§4.2).

> 이 결정이 유효하려면 **음의 힘이 실제로 안 나와야** 한다. 견인 실험 로그에서 ch0 이
> 0 cnt 에 눌러앉는 구간이 보이면 그건 "힘 0" 이 아니라 **클리핑**이다 — `ZERO_MIN_CNT`
> 게이트를 껐으므로 도구는 경고하지 않는다. 사람이 봐야 한다.

### 4.2 ⚠ 새 포화 천장은 이번에 확인하지 못했다

이전 캘리는 **~3234 cnt 에서 하드 포화**를 관측했다. 그 값이 앰프 **출력 전압** 천장이라면
(12bit ADC 상한 4095 보다 낮으니 ADC rail 이 아니라 앰프 쪽일 가능성이 높다) span 을 바꿔도
**cnt 천장은 3234 로 유지**되고, 힘 환산 상한만 내려간다:

| 구성 | 사용 가능 상한 |
|------|----------------|
| 이전 (k=12.63, offset 215) | (3234-215)/12.63 = **239 N** |
| 지금 (k=14.69, offset 10) | (3234-10)/14.69 = **~219 N** (추정) |
| offset 을 300 cnt 로 올리면 | (3234-300)/14.69 = **~200 N** (추정) |

**이 표는 전부 "천장 3234 cnt 가 유지된다"는 가정 위에 있고, 검증하지 않았다.**
이번 최고점은 20.47 kg = 200.7 N (2959 cnt) 로, 천장 추정치 아래에서 멈췄다.
검증하려면 **22.4 kg 이상**의 무게추가 필요하다 (현재 보유분으로는 불가).

> 반대 가능성도 열려 있다 — 천장이 ADC 상한(4095)이라면 지금 상한은 오히려 **278 N** 으로
> 늘었다. 어느 쪽인지는 무게추를 더 확보하기 전엔 알 수 없다.

## 5. 실험에 대한 함의

- **전류 상한 마진이 줄었다.** 이론 slope ~20.7 N/A · 데드밴드 ~8 A 기준으로
  `step_probe` 의 18 A 는 ~207 N 을 낸다. 이전 상한(239 N)에서는 32 N 여유였지만
  **지금 추정 상한(219 N)에서는 12 N 여유**다. §4.2 가 미검증인 동안
  **18 A 를 넘기지 말 것** — 넘기려면 먼저 천장을 실측해야 한다.
- **offset 은 현재 값(10 cnt)으로 확정.** §4.1 의 결정에 따라 음방향을 포기하고 위쪽
  여유를 최대로 쓴다 — offset 을 300 cnt 로 올렸다면 추정 상한이 ~200 N 까지 내려갔을 것이다.
- **구 bag 은 새 상수로 재분석하면 안 된다 — §6.**

## 6. 캘리 상수 갱신 완료 — 구 bag 은 이 상수로 읽으면 안 된다

`analysis/loadcell_cal.json` 을 **새 값(0.068058 N/cnt)으로 갱신**했다.
`traction_analysis.py` 가 기동 시 자동으로 읽는 것을 확인했다 (`LC_N_PER_CNT`, 단위 `N`).

`traction_analysis.py` 는 이 파일을 **전역 상수 하나로** 읽고 날짜별 분기가 없다. 따라서:

> **2026-07-21 상수로 취득한 bag(07-21 ~ 08-20)을 지금 재분석하면 힘이 16.4% 크게 나온다.**
> 경고도, 단위 라벨 변화도 없이 **조용히 틀린다.**

**결정 (2026-08-21): 구 bag 은 폐기 예정이므로 날짜별 분기를 넣지 않는다.** 구 상수는
`loadcell_cal.json` 의 `supersedes` 에 기록만 해 뒀다 — 되살릴 일이 생기면 그 값을 쓴다.
