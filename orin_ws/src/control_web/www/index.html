정지는 arm 을 먼저 내리고 SIGINT → SIGTERM → SIGKILL 순으로 간다 






  

    

      
프로파일

      

        
        
        
        
        
        
      

      

        mode 는 선언이지 전환이 아니다 — 브리지의 auto_mode 와 다르면
        goal 이 거부된다 (05 §2.2). velocity 는 max_abs,
        position 은 range 가 필수다.
      

      

        
        
        
      

      

      
      

        이 곡선은 미리보기다 — 실제 값은 브리지가 YAML 에서 펼친 것이고,
        prbs·noise 는 브리지의 seed 로 정해지므로 여기서는
        모양만 맞다. 점선은 세그먼트 경계.
      

    


    

      
실행

      

        
        
        
        
        대기
      

      

        

      

      

      

      

      

        기록은 CLI 와 같은 모듈(control_cli/record.py)을 쓴다 —
        웹으로 돌린 런도 동일한 schema v2 result.json + 같은 토픽의 bag 이 남아
        분석 파이프라인에 그대로 들어간다. 거부된 런도 기록한다 (왜 거부됐는지가 데이터다).
      

    


    
    

  






  

    

      
레지스터 맵 —

      

        읽기:
        
        
      

      

        회색 행은 미판독이다 — 지금 프리셋도, 마지막 슬롯 READ 도 그 구간을 안 읽었다는 뜻이고,
        섀도에 값이 있어도 그것은 읽은 적 없거나 낡은 값이다. 쓰기 칸은
        CMD_MOTOR·CMD_SYSTEM 에만 생긴다.
        쓰기는 manual 전용이다 (B6) — control 이면 브리지가 거부하고 사유가 아래에 뜬다.
      

      

        
        
        
      

      

    


    

      
커맨드 슬롯

      

      

        control 은 커맨드 전용 슬롯이 0개라 프레임의 양보 tick으로 나간다
        (프레임당 1칸 = 최대 5Hz, 제어 tick 손실 2.5%). RUNNING·STREAM 중에는 양보하지 않는다 —
        실험 시계열에 구멍이 생기기 때문이다.
      

    


    

      
Reboot

      

        
        
        
        3초간 해당 보드 접근이 차단된다 (blackout)
      

      

    


    
    

  









  

    
① 현재 자세

    

      
모터position [deg]velocity [RPM]current [A]cmd

      
    

  


  

    
③ 슬라이더 · ⑤ 조작

    

      
      
      
    

    

    

      아직 만지지 않은 슬라이더는 현재 자세를 따라간다 (run 순간 변위 0).
      한 번 움직이면 조작자 소유가 되어 더 이상 따라가지 않는다 — 되돌리려면 “자세로”.
    

  


  
  


  

    
② 원점 · ④ run · ⑥ stop

    

      
      
      
    

    
브리지 상태를 읽는 중…

  


  

    
순서

    
    
      
  1. ① 현재 자세를 확인한다
    2. 
      
  2. ② 필요하면 원점을 잡는다 — run 전에만 가능하고, auto_mode=DIRECT + 정지 상태여야 한다
    3. 
      
  3. ③ 슬라이더를 시작 위치에 놓는다 (아직 나가지 않는다)
    4. 
      
  4. ④ run — 이 시점부터 슬라이더 값이 모터로 나간다
    5. 
      
  5. ⑤ 슬라이더를 움직이면 모터가 따라온다
    6. 
      
  6. ⑥ stop — 브라우저를 닫거나 응답이 끊겨도 자동으로 stop 된다
    7. 
    

    

      제어 모드·활성 모터 변경은 여기 없다. control_cli config (IDLE 전용)의 몫이다.
      상태는 브리지의 정형 JSON(04 §4)을 그대로 읽는다 — 헤더의 write·preset·clock 이 그 값이다.
    

  


  
  

    
모니터 —

      0 으로 그리면 “안 읽음”이 “정상 0”으로 둔갑한다. 세로 밴드는 50Hz 로 내리면서 보존한
