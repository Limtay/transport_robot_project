        수신은 DPC 가 그 바이트를 받아서 갖고 있다는 뜻이다 —
        그것이 동작했다는 뜻이 아니다. 에코는 멀쩡한데 솔레노이드는 안 움직인다.
        반영 열은 설계상 되먹임 선이 있는 자리(sys_state·lock 접점)를
        가리킬 뿐이고, 레지스터 구현이 끝나기 전까지는 그 값도 보증되지 않는다.
        나머지는 되먹임 선 자체가 없어 눈으로 봐야 한다.
      

      

        127 은 CTRL(0) · HOLD(1) · INIT(2) · ASCEND_1(6) 만 쓸 수 있다.
        펌웨어가 값을 검증 없이 대입하므로 FSM 중간 상태를 쓰면 단계를 건너뛴다 — 브리지가 막는다.
      

    


    
    

      
주행 안전장치 0 수렴 스킵 —

      

        
        
        상한 —
      

      

        기본은 꺼짐이다. 켜면 cmd_vel 이 상한 시간 이상 0 에 머물 때 쓰기를 멈춘다 —
        평지에서는 “0 을 쓴다”와 “안 쓴다”가 같은 결과라 버스를 아끼는 최적화다.
      

      

        ⚠ 경사에서는 다르다. 쓰기가 끊기면 ECU 의 cmd_write_tick 갱신이 멈추고
        100ms(AUTO_TIMEOUT) 뒤 ECU 가 명령을 무효화한다. 정지 유지 중이라면
        “0 을 유지하라”가 “명령이 없다”로 바뀐다 — 경사에서는 켜지 말 것.
      

      

        토픽 미수신(0.1s) 스킵은 이것과 다른 축이며 항상 켜져 있다
        (cmd_vel_guard_enable). 그쪽은 “상위가 죽었다”이고, 이쪽은
        “살아 있는데 0 을 준다”라 그 0 은 의도된 지시다.
      

    


    
    

      
jeongae 자동 전개
        단계 —
          · 대기 —

      

        
        
        
        lock —
      

      

        전개 시작은 토픽(/jeongae)이라 수락 여부가 응답으로 오지 않는다 —
        단계 표시로 확인할 것. lock 이 걸려 있으면 조용히 무시된다.
        시퀀스가 도는 동안 위 표의 127 입력이 잠긴다 (배타).
      

      

        단계: ESTOP_SET → DPC_STATE_CHECK → DPC_SET_AUTO → DPC_DEPLOY →
        DPC_WAIT_CAMERA → CAMERA_ACTION → DPC_RETRACT → DPC_WAIT_RETRACT → ESTOP_RELEASE.
        각 대기 단계는 상한을 넘으면 Abort 한다 — 전개 도중 매달려 있는 것이 가장 나쁘다.

        보드:
        
        
        
        보드를 바꾸면 편집 중인 값은 버린다 — 주소가 같아도 뜻이 다르다
      

      

        읽기:
        
        
      

      

        표는 10Hz 로 자동 갱신된다. 이 갱신은 버스를 건드리지 않는다 —
        브리지 섀도를 덤프할 뿐이라 통신 부하가 0 이다. 위의 읽기 버튼이
        실제로 보드에 READ 를 보내는 것이고, 표는 그 결과가 섀도에 들어온 것을 비춘다.
      

      

        age 열이 그 값을 마지막으로 읽은 지 얼마나 됐는지다. 주기 슬롯이 덮는 구간은
        ms 대이고, 기동 전체읽기로만 채워진 구간은 분 단위로 늘어난다 — 둘 다 실제로
        읽은 값이지만 신선도가 다르다. 회색 행(미판독)은 한 번도 안 읽은
        자리이고, 거기 보이는 0 은 값이 아니라 섀도 초기값이다.
        
쓰기 칸은 rw=쓰기가능 블록에만 생긴다.
        쓰기는 정지 상태에서만 된다 — 달리는 중이면 브리지가 거부하고 사유가 아래에 뜬다.
        (모드 제한은 없다 — 09 §5.4 ②/U7 에서 풀렸고 어느 모드에서든 쓸 수 있다.)
      

      

        
        
        
      

      

    


    

      
커맨드 슬롯 ECU 전용

      

      

        control 은 커맨드 전용 슬롯이 0개라 프레임의 양보 tick으로 나간다
        (프레임당 1칸 = 최대 5Hz, 제어 tick 손실 2.5%). RUNNING·STREAM 중에는 양보하지 않는다 —
        실험 시계열에 구멍이 생기기 때문이다.
