# BMS CAN 통신 프로토콜 (PRA ↔ BMS)

> 상위: [pra_overview.md](pra_overview.md) · 페리페럴: [pra_peri.md](pra_peri.md) §CAN1 · 레지스터: [pra_register.md](pra_register.md) §SENSOR/BMS
> 원본: [raw/BMS protocol.md](raw/BMS%20protocol.md) (벤더 프로토콜 + PCAN 실측 원본)
> 작성: 2026-10-10 — PCAN 실기 통신 검증 기반 정리. **Step 8(BMS CAN 파서) 착수 전 참조 문서**

PRA(STM32, CAN1)가 마스터로 BMS에 **요청(req)→응답(resp)** 폴링하여 팩 상태를 수집하는 규약. 벤더 표준 프로토콜 + 유저 PCAN 실측 패킷 디코드를 정리.

---

## 1. 물리 계층 / 프레임 규격

| 항목 | 값 |
|------|-----|
| 프로토콜 | CAN 2.0B |
| 비트레이트 | **250 kbps** |
| 식별자 | **29-bit 확장(Extended) ID** (예: `0x18900140`) |
| DLC | **8 bytes 고정** |
| 요청 데이터 | 8바이트 전부 `0x00` |
| 통신 방식 | 마스터(PRA) 요청 → BMS 응답 (폴링) |

> STM 측: bxCAN 필터를 **확장 ID**로 구성. 응답 수신 필터는 `0x18xx4001` 패턴(호스트=0x40 목적지).

---

## 2. 식별자(ID) 구조

29-bit ID = **우선순위(8) + 데이터ID(8) + 목적지주소(8) + 송신원주소(8)**

| 바이트 | 필드 | 요청(PRA→BMS) | 응답(BMS→PRA) |
|--------|------|---------------|---------------|
| [31:24] | 우선순위 | `0x18` | `0x18` |
| [23:16] | 데이터 ID | `0x90`~`0x98` | 동일 ID 에코 |
| [15:8]  | 목적지 주소 | `0x01` (BMS) | `0x40` (호스트) |
| [7:0]   | 송신원 주소 | `0x40` (호스트) | `0x01` (BMS) |

- **호스트(PRA) 주소 = 상시 `0x40`**, **BMS 주소 = 상시 `0x01`**. 실질 변수는 **데이터 ID 1바이트뿐**.
- 요청 ID = `0x18 [ID] 01 40`, 응답 ID = `0x18 [ID] 40 01`.

| 데이터 ID | 요청 ID | 응답 ID |
|-----------|---------|---------|
| 0x90 | `0x18900140` | `0x18904001` |
| 0x92 | `0x18920140` | `0x18924001` |
| 0x98 | `0x18980140` | `0x18984001` |

> **바이트 오더 = Big-Endian** (멀티바이트 값은 Byte0=MSB). PCAN 실측으로 확정 (§5).

## 3. 사용 데이터 ID — **필수 3종** (유저 확정)

PRA 시스템에서 실제 소비하는 값은 아래 3종.

### 3-1. `0x90` — 총전압 / 전류 / SOC

| 바이트     | 필드                              | 스케일/오프셋                  | 비고                  |
| ------- | ------------------------------- | ------------------------ | ------------------- |
| Byte0~1 | 누적 총전압 Cumulative total voltage | ×0.1 V                   | **사용** (팩 총전압)      |
| Byte2~3 | 측정 총전압 Gather total voltage     | ×0.1 V                   | 예비(Reserved), 실측 0  |
| Byte4~5 | 전류 Current                      | **30000 offset**, ×0.1 A | 부호: (raw−30000)×0.1 |
| Byte6~7 | SOC                             | ×0.1 %                   | **사용**              |

### 3-2. `0x92` — 최고/최저 셀 온도

| 바이트     | 필드                        | 스케일/오프셋              | 비고              |
| ------- | ------------------------- | -------------------- | --------------- |
| Byte0   | **최고 셀 온도** Max cell temp | **40 offset**, ×1 °C | **사용** (raw−40) |
| Byte1   | 최고온도 셀 번호                 | —                    |                 |
| Byte2   | 최저 셀 온도 Min cell temp     | 40 offset, ×1 °C     | (raw−40)        |
| Byte3   | 최저온도 셀 번호                 | —                    |                 |
| Byte4~7 | —                         | —                    | 미정의(실측 0)       |

> 유저 필수값은 **Byte0(최고 셀 온도)** 만. 레지스터는 `max_cell_temp`(addr51) 1개만 보유(min·셀번호 폐기, §6).

### 3-3. `0x98` — 배터리 고장상태 (비트 플래그, `0`=정상 / `1`=에러)

바이트별 비트 플래그. **엔디안 무관**(바이트 단위).

**Byte0 — 전압 경고**
| bit | 의미 |
|-----|------|
| 0 | 셀 과전압 1단계 |
| 1 | 셀 과전압 2단계 |
| 2 | 셀 저전압 1단계 |
| 3 | 셀 저전압 2단계 |
| 4 | 팩 과전압 1단계 |
| 5 | 팩 과전압 2단계 |
| 6 | 팩 저전압 1단계 |
| 7 | 팩 저전압 2단계 |

**Byte1 — 온도 경고**
| bit | 의미 |
|-----|------|
| 0 | 충전 과온도 1단계 |
| 1 | 충전 과온도 2단계 |
| 2 | 충전 저온도 1단계 |
| 3 | 충전 저온도 2단계 |
| 4 | 방전 과온도 1단계 |
| 5 | 방전 과온도 2단계 |
| 6 | 방전 저온도 1단계 |
| 7 | 방전 저온도 2단계 |

**Byte2 — 전류/SOC 경고**
| bit | 의미 |
|-----|------|
| 0 | 충전 과전류 1단계 |
| 1 | 충전 과전류 2단계 |
| 2 | 방전 과전류 1단계 |
| 3 | 방전 과전류 2단계 |
| 4 | SOC 높음 1단계 |
| 5 | SOC 높음 2단계 |
| 6 | SOC 낮음 1단계 |
| 7 | SOC 낮음 2단계 |

**Byte3 — 편차 경고** (bit4~7 Reserved)
| bit | 의미 |
|-----|------|
| 0 | 전압 편차 과대 1단계 |
| 1 | 전압 편차 과대 2단계 |
| 2 | 온도 편차 과대 1단계 |
| 3 | 온도 편차 과대 2단계 |

**Byte4 — MOS 경고**
| bit | 의미 |
|-----|------|
| 0 | 충전 MOS 과온도 |
| 1 | 방전 MOS 과온도 |
| 2 | 충전 MOS 온도센서 오류 |
| 3 | 방전 MOS 온도센서 오류 |
| 4 | 충전 MOS 접착(단락) 오류 |
| 5 | 방전 MOS 접착(단락) 경고 |
| 6 | 충전 MOS 단선 오류 |
| 7 | 방전 MOS 단선 오류 |

**Byte5 — 내부 모듈 오류**
| bit | 의미 |
|-----|------|
| 0 | AFE 수집 칩 오류 |
| 1 | 셀 전압 수집 단선 오류 |

**Byte6 — 검출 모듈 오류** (bit4~7 Reserved)
| bit | 의미 |
|-----|------|
| 0 | 전류 모듈 오류 |
| 1 | 팩 전압 검출 모듈 오류 |
| 2 | 단락(쇼트) 보호 오류 |

**Byte7 — 고장 코드 (Fault code)** : 비트 플래그가 아닌 **바이트 값**(벤더 정의 코드)

> ⚠ 0x98 은 **8바이트 전부 유의미**. 레지스터는 `error_lsb`(Byte0~3) + `error_hsb`(Byte4~7) u32×2 로 **전체 보존**(§6).

## 5. PCAN 실측 로그 + 디코드 (2026-10-10, 유저)

형식: `ID / DLC / DATA(hex)`. 요청 데이터는 전부 `00`.

### 0x90 — 전압/전류/SOC
```
send    : 18900140h / 8 / 00 00 00 00 00 00 00 00
receive : 18904001h / 8 / 02 1A 00 00 75 30 02 A8
```
- 누적 총전압 = `0x021A`(538) ×0.1 = **53.8 V**
- 측정 총전압(예비) = `0x0000` = 0
- 전류 = `0x7530`(30000) − 30000 = 0 → **0.0 A** (무부하)
- SOC = `0x02A8`(680) ×0.1 = **68.0 %**

### 0x92 — 최고/최저 온도
```
send    : 18920140h / 8 / 00 00 00 00 00 00 00 00
receive : 18924001h / 8 / 40 01 40 01 00 00 00 00
```
- 최고 셀 온도 = `0x40`(64) − 40 = **24 °C** (셀 #1)
- 최저 셀 온도 = `0x40`(64) − 40 = **24 °C** (셀 #1)

### 0x98 — 배터리 고장상태
```
send    : 18980140h / 8 / 00 00 00 00 00 00 00 00
receive : 18984001h / 8 / 00 00 00 00 00 00 00 00
```
- Byte0~7 전부 `0x00` → **에러 없음(정상)**. 8바이트 모두 유의미(전압/온도/전류·SOC/편차/MOS/내부모듈/검출모듈/고장코드)

### (참고) 0x91 / 0x93 — 함께 수집된 샘플
```
0x91 recv: 18914001h / 8 / 0F 0B 02 0F 09 01 00 00
   → 최고 셀전압 0x0F0B=3851 mV(#2) / 최저 0x0F09=3849 mV(#1)
0x93 recv: 18934001h / 8 / 00 01 01 A5 00 00 5C F8
   → state 0(정지) / 충MOS ON / 방MOS ON / life 0xA5=165 / 잔여 0x00005CF8=23800 mAh
```

## 6. 레지스터 매핑 (SENSOR/BMS, addr 48~64) — (2026-10-13: SENSOR/ADC int16 확장으로 45→48 밀림)

`rd_register_pra.h` `DATA_SENSOR_BMS_t` = 필수 3종 전용(0x93 폐기, 0x98 전체 8바이트 수용, 전류 signed). 영역 **17B(addr 48~64)**.

| 레지스터 addr | 필드 | 타입 | 원천 ID | 변환 |
|---------------|------|------|---------|------|
| 48 | `voltage` | uint16 | **0x90** B0~1 | ×0.1 V (팩 총전압) |
| 50 | `current` | **int16 (signed)** | **0x90** B4~5 | (raw−30000)×0.1 A → signed 저장 |
| 52 | `soc` | uint16 | **0x90** B6~7 | ×0.1 % |
| 54 | `max_cell_temp` | uint8 | **0x92** B0 | **raw 그대로(40 offset 보존)** — 리더가 −40. uint8 라 음수 못 담아 오프셋 유지(current 와 비대칭) |
| 55 | `error_lsb` | uint32 | **0x98** B0~3 | error code [0:3] (전압/온도/전류·SOC/편차) |
| 59 | `error_hsb` | uint32 | **0x98** B4~7 | error code [4:7] (MOS/내부모듈/검출모듈/고장코드) |
| 63 | `delta_tick` | uint8 | (PRA 내부) | **×0.1 s** (BMS 예외 스케일, 1Hz 로깅용 — 타 센서 ×0.1ms 와 다름), 0xFF=25.5s↑ 지연 오염 |
| 64 | `state` | STATE_t | (PRA 내부) | CAN1 채널 종합 상태 |

**반영 확정 사항**
- ✅ **전류 offset 30000** 확정(0x7530=30000이 0A). 필드를 **int16 signed** 로 변경해 부호 수용(저장 시 raw−30000)
- ✅ **0x98 전체 8바이트** → `error_lsb`+`error_hsb` u32×2 로 보존. B7(고장코드)까지 포함
- ✅ **0x93 폐기**: `bms_state`/`bms_life`/`soh` 필드 제거. `BMS_STATE_*` 매크로는 사용처 없으면 정리 대상
- ✅ **0x92 간소화**: `max_cell_temp` 1개만(min·셀번호 폐기)

**✅ 헤더 `#define` 동기화 완료 (2026-10-10)**
struct(17B, 2026-10-13 기준 addr 48~64)에 맞춰 전부 반영:
- `REG_SENSOR_BMS_SIZE` 16→**17**
- `REG_CMD_POWER_OFFSET` 61→**62**, `REG_CMD_POWER_S/E_OFFSET` 61/63→**62/64** (BMS +1 밀림)
- `REG_RSVD1_OFFSET` 64→**65**, `REG_RSVD1_SIZE` 16→**15** (총 256 유지)
- `REGISTER_t.reserved1[16]→[15]` + 멤버 주석 주소(62/65) 갱신 — **총합 256 유지의 핵심**
- 상단 영역 레이아웃 주석 `[45:61]17B`·`[62:64]`·`[65:79]15B` 갱신
- `rd_map_pra.c` LUT·cmd 쓰기판정은 `#define` 심볼 참조라 자동 반영(주석만 동기 정정)

**✅ static_assert 활성화 (2026-10-10)**: 7개 size 검증 주석 해제. `DATA_SENSOR_BMS_t==17`·`REGISTER_t==256` 등 컴파일 타임 보증. ⚠ **C11 필요**(`static_assert`=`<assert.h>` 매크로) — CubeIDE 프로젝트 C 표준이 gnu11+ 인지 사용자 빌드 확인.

**🟡 잔여(무관, 코드 후속)**: addr23 `sys_state` 인라인 주석이 구값(MANUAL/AUTO/ESTOP) — 블록주석 신값(INIT/RUN_OFF/RUN_TRN/RUN_ON/FAULT)과 불일치. `BMS_STATE_*` 매크로 orphan(0x93 폐기) — 정리 대상.

## 7. 구현 메모 (Step 8 착수 시)

- **폴링 루프**: 필수 3 ID(0x90·0x92·0x98) 요청(데이터 8×`0x00`) → 응답 수신 파싱. 주기/타임아웃은 다른 센서 주기와 정합.
- **확장 ID 필터**: 수신 `0x1890 4001`/`0x1892 4001`/`0x1898 4001` 매칭(또는 `0x18xx4001` 마스크 + ID 분기).
- **엔디안**: 멀티바이트(전압/전류/SOC)는 **big-endian** 조립 — `(B0<<8)|B1`.
- **스케일/오프셋 변환(레지스터 저장 기준)**: 전압·SOC = raw 그대로(uint16, 리더가 ×0.1), **전류 = (int16)(raw−30000)**(오프셋 **제거**, 리더가 ×0.1 A), **온도 = raw 그대로(uint8, 40 offset **보존**, 리더가 −40)**. ⚠ **current 는 오프셋 제거(int16), temp 는 오프셋 보존(uint8)** — uint8 이 음수를 못 담기 때문(필드 타입이 강제한 비대칭). Orin rd_register_pcu.hpp 변환 시 필드별로 다르게 적용할 것
- **0x98 저장**: Byte0~3 → `error_lsb`(u32), Byte4~7 → `error_hsb`(u32). 바이트 순서 보존(비트 플래그라 엔디안 무관하나 B0→LSB 바이트 배치 규칙 코드에 명시).
- **Degraded/Checker**: CAN1 = `HW_BIT_CAN1`/`degraded_cnt[0]`. 응답 미수신 시 채널 STATE_t(addr**61**) 반영 (ECU/DPC_B Checker 패턴).
- **0x98 활용**: `error_lsb|error_hsb` OR 집계로 BMS 결함 판정 → 전원 FSM FAULT 연계 여부는 정책 결정(현재 opmode §4-7 FAULT 정책과 분리 검토, BMS 결함 등급별 대응 TODO).
